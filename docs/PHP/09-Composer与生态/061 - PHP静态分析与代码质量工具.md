---# PHP静态分析与代码质量工具

PHP是动态语言，很多错误在运行时才暴露。静态分析工具在编码阶段就能发现bug，是现代PHP开发流程的必备环节。

## PHPStan：静态分析

### 安装与级别说明

PHPStan从级别0（最宽松）到级别9（最严格），逐步提升检查强度：

```bash
composer require --dev phpstan/phpstan
```

| 级别 | 检查内容 |
|------|----------|
| 0 | 基本检查、未定义变量、未定义方法 |
| 1-3 | 类型推断、参数类型检查 |
| 4-5 | 返回类型检查、null安全 |
| 6-7 | 严格类型检查、泛型支持 |
| 8 | 显式类型标注要求、mixed类型警告 |
| 9 | 最严格，要求所有代码都有完整类型标注 |

### 配置文件

```yaml
# PHP静态分析与代码质量工具
parameters:
    level: 8
    paths:
        - app
        - src
    excludePaths:
        - app/Console/Kernel.php
    ignoreErrors:
        - '#Call to an undefined method.*#'
    bootstrapFiles:
        - phpstan-bootstrap.php
    universalObjectCratesClasses:
        - stdClass
    treatPhpDocTypesAsCertain: true
```

### 常见错误与修复

```php
<?php
// PHPStan报错示例与修复

// Level 0: 未定义变量
function process() {
    echo $name; // Undefined variable: $name
}
// 修复:
function process(): void {
    $name = 'default';
    echo $name;
}

// Level 5: 可能的null
function findUser(int $id): ?User {
    return User::find($id); // 可能返回null
}
$user = findUser(1);
echo $user->name; // 错误: $user可能是null
// 修复:
if ($user !== null) {
    echo $user->name;
}

// Level 6: 返回类型不匹配
function getItems(): array {
    return ['a', 1, true]; // 错误: 混合类型数组
}
// 修复:
/** @return string[] */
function getItems(): array {
    return ['a', 'b', 'c'];
}
// 更好: 使用PHP 8的类型声明
function getItems(): array { // 或 list<string>
    return ['a', 'b', 'c'];
}

// Level 8: 缺少类型标注
function calculate($a, $b) { // Parameter $a has no type specified
    return $a + $b;
}
// 修复:
function calculate(int $a, int $b): int {
    return $a + $b;
}
```

### PHPStan泛型支持

```php
<?php
/**
 * @template T
 */
class Collection
{
    /** @param array<T> $items */
    public function __construct(private array $items) {}
    
    /** @return T|null */
    public function first(): mixed
    {
        return $this->items[0] ?? null;
    }
    
    /** @param callable(T): bool $filter */
    public function filter(callable $filter): self
    {
        return new self(array_filter($this->items, $filter));
    }
}

/** @var Collection<User> $users */
$users = new Collection([new User('Alice'), new User('Bob')]);
$first = $users->first(); // PHPStan知道$first是User|null
```

```bash
composer require --dev vimeo/psalm
```

```xml
<!-- psalm.xml -->
<?xml version="1.0"?>
```

## PHP-CS-Fixer：代码风格

```bash
composer require --dev friendsofphp/php-cs-fixer
```

```php
<?php
// .php-cs-fixer.php
$finder = PhpCsFixer\Finder::create()
    ->in([__DIR__ . '/app', __DIR__ . '/src', __DIR__ . '/tests'])
    ->notPath('*.blade.php');

return (new PhpCsFixer\Config())
    ->setRules([
        '@PHP82Migration' => true,
        '@PSR12' => true,
        '@PSR12:risky' => true,
        'strict_param' => true,
        'array_syntax' => ['syntax' => 'short'],
        'ordered_imports' => true,
        'no_unused_imports' => true,
        'declare_strict_types' => true,
        'fully_qualified_strict_types' => true,
        'no_superfluous_phpdoc_tags' => true,
        'phpdoc_order' => true,
        'single_quote' => true,
        'trailing_comma_in_multiline' => true,
        'blank_line_before_statement' => [
            'statements' => ['return', 'try'],
        ],
    ])
    ->setFinder($finder)
    ->setRiskyAllowed(true);
```

```bash
# 检查（不修改）
php-cs-fixer fix --dry-run --diff

# 自动修复
php-cs-fixer fix
```

## Rector：自动升级重构

```bash
composer require --dev rector/rector
```

```php
<?php
// rector.php
use Rector\Config\RectorConfig;
use Rector\Set\ValueObject\SetList;
use Rector\TypeDeclaration\Rector\Property\TypedPropertyFromStrictConstructorRector;

return RectorConfig::configure()
    ->withPaths([__DIR__ . '/app', __DIR__ . '/src'])
    ->withPhpSets(php83: true)
    ->withSets([
        SetList::CODE_QUALITY,
        SetList::DEAD_CODE,
        SetList::TYPE_DECLARATION,
        SetList::PRIVATIZATION,
    ])
    ->withRules([
        TypedPropertyFromStrictConstructorRector::class,
    ]);
```

```bash
# 预览变更
rector process --dry-run

# 应用变更
rector process

# 只运行特定规则
rector process --rule=TypedPropertyFromStrictConstructorRector
```

## pre-commit hook集成

```bash
#!/bin/bash
# .git/hooks/pre-commit

# 只检查暂存的文件
STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM -- '*.php')

if [ -z "$STAGED_FILES" ]; then
    exit 0
fi

echo "Running PHP-CS-Fixer..."
for FILE in $STAGED_FILES; do
    php-cs-fixer fix "$FILE" --config=.php-cs-fixer.php
    git add "$FILE"
done

echo "Running PHPStan..."
phpstan analyse --memory-limit=512M

if [ $? -ne 0 ]; then
    echo "PHPStan found errors. Fix them before committing."
    exit 1
fi

echo "All checks passed!"
exit 0
```

## 面试常见追问

**Q: PHPStan和Psalm选哪个？**
A: PHPStan生态更广、社区更活跃、框架集成更好（Laravel/Symfony都有插件）。Psalm类型推断更精确，taint分析是独特优势。新项目推荐PHPStan，需要安全分析加Psalm。

**Q: 静态分析能替代测试吗？**
A: 不能。静态分析检查类型正确性和常见bug模式，但不能验证业务逻辑正确性。`function add(int $a, int $b): int { return $a - $b; }` 静态分析不报错，但逻辑是错的。

**Q: 从级别0升到8需要多久？**
A: 取决于代码库质量。建议每次升一级，修完所有错误再升下一级。老旧项目可能需要数周。新项目直接从级别6开始。

**Q: CI中怎么集成这些工具？**
A: 按速度排序：CS-Fixer（秒级）→ PHPStan（分钟级）→ PHPUnit（分钟级）。CI中先用CS-Fixer检查格式，再跑PHPStan，最后跑测试。任一环节失败就阻断。
