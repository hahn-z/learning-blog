---# PHP数据库迁移管理

## 为什么需要数据库迁移

手动执行SQL修改数据库结构的问题：
- 没有版本记录，不知道哪个环境执行了哪些变更
- 多人协作时互相覆盖
- 无法回滚（线上出问题怎么办？）
- 新环境搭建困难

数据库迁移工具将每次Schema变更记录为版本化的PHP文件，像Git管理代码一样管理数据库结构。

### 常用命令

```bash
# 创建迁移文件
vendor/bin/phinx create CreateUserTable

# 执行迁移（所有未执行的）
vendor/bin/phinx migrate
vendor/bin/phinx migrate -e production

# 回滚到上一个版本

# 回滚到指定版本
vendor/bin/phinx rollback -t 20260531000000
```

## 迁移文件编写

### 基本结构

```php
<?php
// db/migrations/20260531100000_create_users_table.php
declare(strict_types=1);

use Phinx\Migration\AbstractMigration;

class CreateUsersTable extends AbstractMigration
{
    public function change(): void
    {
        $table = $this->table('users', ['id' => false, 'primary_key' => ['id']]);
        $table
            ->addColumn('id', 'integer', ['identity' => true, 'signed' => false])
            ->addColumn('name', 'string', ['limit' => 100, 'null' => false])
            ->addColumn('email', 'string', ['limit' => 255, 'null' => false])
            ->addColumn('password', 'string', ['limit' => 255, 'null' => false])
            ->addColumn('role', 'enum', ['values' => ['admin', 'user', 'editor'], 'default' => 'user'])
            ->addColumn('status', 'boolean', ['default' => true])
            ->addColumn('created_at', 'timestamp', ['default' => 'CURRENT_TIMESTAMP'])
            ->addColumn('updated_at', 'timestamp', ['null' => true, 'update' => 'CURRENT_TIMESTAMP'])
            ->addIndex(['email'], ['unique' => true, 'name' => 'uk_users_email'])
            ->addIndex(['role'], ['name' => 'idx_users_role'])
            ->addIndex(['created_at'], ['name' => 'idx_users_created_at'])
            ->create();
    }
}
```

### change() vs up()/down()

```php
<?php
// change()：Phinx自动推断回滚操作
// 适合简单迁移（createTable, addColumn等）
public function change(): void
{
    $this->table('posts')
        ->addColumn('title', 'string')
        ->addColumn('body', 'text')
        ->create();
    // 回滚时Phinx自动知道要drop表
}

// up()/down()：需要手动写正向和反向操作
// 适合复杂迁移、数据迁移
public function up(): void
{
    // 添加列
    $this->table('users')
        ->addColumn('nickname', 'string', ['limit' => 50, 'after' => 'name'])
        ->update();

    // 数据迁移：从name提取nickname
    $this->execute("UPDATE users SET nickname = SUBSTRING_INDEX(name, ' ', 1)");
}

public function down(): void
{
    $this->table('users')
        ->removeColumn('nickname')
        ->update();
}
```

### 复杂迁移示例

```php
<?php
// 订单表创建（含外键）
declare(strict_types=1);

use Phinx\Migration\AbstractMigration;

class CreateOrdersTable extends AbstractMigration
{
    public function change(): void
    {
        $table = $this->table('orders');
        $table
            ->addColumn('user_id', 'integer', ['signed' => false])
            ->addColumn('order_no', 'string', ['limit' => 32])
            ->addColumn('total_amount', 'decimal', ['precision' => 10, 'scale' => 2, 'default' => 0])
            ->addColumn('status', 'enum', [
                'values' => ['pending', 'paid', 'shipped', 'completed', 'cancelled'],
                'default' => 'pending',
            ])
            ->addColumn('paid_at', 'timestamp', ['null' => true])
            ->addColumn('created_at', 'timestamp', ['default' => 'CURRENT_TIMESTAMP'])
            ->addColumn('updated_at', 'timestamp', ['null' => true, 'update' => 'CURRENT_TIMESTAMP'])
            ->addIndex(['order_no'], ['unique' => true])
            ->addIndex(['user_id'], ['name' => 'idx_orders_user'])
            ->addIndex(['status', 'created_at'], ['name' => 'idx_orders_status_date'])
            ->addForeignKey('user_id', 'users', 'id', [
                'delete' => 'RESTRICT',
                'update' => 'CASCADE',
                'constraint' => 'fk_orders_user',
            ])
            ->create();
    }
}

// 数据迁移：安全修改大表
class AddAvatarToUsers extends AbstractMigration
{
    public function up(): void
    {
        // 1. 先加列（允许NULL）
        $this->table('users')
            ->addColumn('avatar', 'string', ['limit' => 500, 'null' => true, 'after' => 'email'])
            ->update();

        // 2. 分批填充默认值（大表安全）
        $batchSize = 1000;
        $offset = 0;
        $defaultAvatar = '/images/default-avatar.png';

        do {
            $affected = $this->execute(
                "UPDATE users SET avatar = '{$defaultAvatar}'
                 WHERE avatar IS NULL LIMIT {$batchSize}"
            );
            $offset += $batchSize;
            usleep(100000); // 100ms间隔，减少主库压力
        } while ($affected > 0);

        // 3. 改为NOT NULL
        $this->execute("ALTER TABLE users MODIFY avatar VARCHAR(500) NOT NULL");
    }

    public function down(): void
    {
        $this->table('users')->removeColumn('avatar')->update();
    }
}
```

## 版本回滚策略

```php
<?php
// 回滚策略选择

// 1. 开发环境：随意回滚
// vendor/bin/phinx rollback -t 0  // 回到初始状态

// 2. 生产环境：不回滚，写修复迁移
// 如果迁移有问题，不要rollback，而是写一个新的迁移来修复
// 原因：rollback可能导致数据丢失

// 错误的迁移
class AddWrongColumn extends AbstractMigration
{
    public function change(): void
    {
        $this->table('users')
            ->addColumn('wrong_col', 'string') // 发现不需要这个列
            ->update();
    }
}

// 修复迁移（新建，不回滚）
class RemoveWrongColumn extends AbstractMigration
{
    public function up(): void
    {
        $this->table('users')->removeColumn('wrong_col')->update();
    }

    public function down(): void
    {
        $this->table('users')
            ->addColumn('wrong_col', 'string', ['null' => true])
            ->update();
    }
}

// 3. CI/CD集成
// deploy.sh
// vendor/bin/phinx migrate -e production
// 如果失败，自动回滚
// vendor/bin/phinx rollback -e production
```

## 面试常见追问

**Q: Phinx和Laravel Migration有什么区别？**
A: Phinx是独立的PHP迁移库，不依赖任何框架。Laravel Migration是Laravel框架的一部分，与Eloquent ORM深度集成。核心区别：Phinx用`$this->table()`流畅接口，Laravel用`Schema::create()`门面。功能基本相同，Phinx更适合非Laravel项目。

**Q: 生产环境能回滚吗？**
A: 技术上可以，但**不推荐**。原因：1) DROP COLUMN会丢失数据；2) DROP TABLE更是灾难性的；3) 数据迁移（如拆列、合并）通常不可逆。正确做法是写"修复迁移"——创建新的迁移来撤销错误变更。只有刚执行的空迁移（还没写数据）才考虑回滚。

**Q: 如何在迁移中安全修改大表？**
A: 原则：1) 先加列（允许NULL），再填充数据，最后改NOT NULL；2) 分批操作，每批加sleep；3) 避免在高峰期执行；4) MySQL 8.0的`ALGORITHM=INPLACE`可以不锁表加列；5) 超大表考虑用pt-online-schema-change工具。
