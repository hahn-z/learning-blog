---# PDO事务与并发控制

## 事务基础

### ACID与PDO事务API

```php
<?php
$pdo = new PDO('mysql:host=127.0.0.1;dbname=myapp;charset=utf8mb4', 'root', '', [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
]);

// 转账事务：A给B转账100元
function transfer(PDO $pdo, int $from, int $to, float $amount): void
{
    $pdo->beginTransaction();

    try {
        // 1. 检查余额
        $stmt = $pdo->prepare('SELECT balance FROM accounts WHERE id = ? FOR UPDATE');
        $stmt->execute([$from]);
        $balance = $stmt->fetchColumn();

        if ($balance < $amount) {
            throw new RuntimeException('余额不足');
        }

        // 2. 扣款
        $pdo->prepare('UPDATE accounts SET balance = balance - ? WHERE id = ?')
            ->execute([$amount, $from]);

        // 3. 加款
        $pdo->prepare('UPDATE accounts SET balance = balance + ? WHERE id = ?')
            ->execute([$amount, $to]);

        // 4. 记录流水
        $pdo->prepare('INSERT INTO transactions (from_id, to_id, amount) VALUES (?, ?, ?)')
            ->execute([$from, $to, $amount]);

        $pdo->commit();
    } catch (Throwable $e) {
        $pdo->rollBack();
        throw $e;
    }
}
```

### 嵌套事务与Savepoint

```php
<?php
// MySQL不支持真正的嵌套事务，但支持SAVEPOINT
function nestedTransaction(PDO $pdo, callable $callback): mixed
{
    static $level = 0;

    if ($level === 0) {
        $pdo->beginTransaction();
    } else {
        $pdo->exec("SAVEPOINT SP{$level}");
    }

    $level++;

    try {
        $result = $callback($pdo);

        $level--;

        if ($level === 0) {
            $pdo->commit();
        } else {
            $pdo->exec("RELEASE SAVEPOINT SP{$level}");
        }

        return $result;
    } catch (Throwable $e) {
        $level--;

        if ($level === 0) {
            $pdo->rollBack();
        } else {
            $pdo->exec("ROLLBACK TO SAVEPOINT SP{$level}");
        }

        throw $e;
    }
}

// 使用
nestedTransaction($pdo, function (PDO $pdo) {
    $pdo->exec("INSERT INTO orders ...");

    nestedTransaction($pdo, function (PDO $pdo) {
        $pdo->exec("INSERT INTO order_items ...");
        // 如果这里失败，只回滚order_items，外层orders保留
    });
});
```

## 隔离级别

### MySQL四种隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | 性能 |
|------|------|-----------|------|------|
| READ UNCOMMITTED | ✅可能 | ✅可能 | ✅可能 | 最高 |
| READ COMMITTED | ❌不会 | ✅可能 | ✅可能 | 高 |
| **REPEATABLE READ** | ❌不会 | ❌不会 | ✅可能* | 中（MySQL默认） |
| SERIALIZABLE | ❌不会 | ❌不会 | ❌不会 | 最低 |

*MySQL InnoDB通过Next-Key Lock在RR级别基本消除了幻读。

```php
<?php
// 查看当前隔离级别
$row = $pdo->query("SELECT @@transaction_isolation")->fetch();
echo $row[0]; // REPEATABLE-READ

// 设置隔离级别（必须在事务开始前设置）
$pdo->exec("SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED");
$pdo->beginTransaction();
// ...
$pdo->commit();
```

### 隔离级别实战演示

```php
<?php
// 不可重复读示例（READ COMMITTED下发生）
// 事务A
$pdoA->exec("SET TRANSACTION ISOLATION LEVEL READ COMMITTED");
$pdoA->beginTransaction();
$balance1 = $pdoA->query("SELECT balance FROM accounts WHERE id = 1")->fetchColumn();
// balance1 = 1000

// 事务B（此时提交了更新）
$pdoB->exec("UPDATE accounts SET balance = 800 WHERE id = 1");
$pdoB->commit(); // 或自动提交

// 事务A再次读取
$balance2 = $pdoA->query("SELECT balance FROM accounts WHERE id = 1")->fetchColumn();
// READ COMMITTED: balance2 = 800（不可重复读！同一事务两次读结果不同）
// REPEATABLE READ: balance2 = 1000（一致）

$pdoA->commit();
```

## 悲观锁：SELECT FOR UPDATE

```php
<?php
// 悲观锁：假设一定会冲突，先加锁再操作
// 场景：库存扣减

function deductStock(PDO $pdo, int $productId, int $quantity): bool
{
    $pdo->beginTransaction();

    try {
        // FOR UPDATE：给这行加排他锁，其他事务必须等待
        $stmt = $pdo->prepare('SELECT stock FROM products WHERE id = ? FOR UPDATE');
        $stmt->execute([$productId]);
        $stock = (int)$stmt->fetchColumn();

        if ($stock < $quantity) {
            $pdo->rollBack();
            return false;
        }

        $pdo->prepare('UPDATE products SET stock = stock - ? WHERE id = ?')
            ->execute([$quantity, $productId]);

        $pdo->commit();
        return true;
    } catch (Throwable $e) {
        $pdo->rollBack();
        throw $e;
    }
}

// FOR UPDATE变种
// SELECT ... FOR UPDATE        — 排他锁（写锁），阻止其他事务读写
// SELECT ... LOCK IN SHARE MODE — 共享锁（读锁），阻止写但允许读
// FOR UPDATE NOWAIT            — 不等待，锁冲突立即报错（MySQL 8.0+）
// FOR UPDATE SKIP LOCKED       — 跳过已锁定的行（MySQL 8.0+）

// SKIP LOCKED实用场景：任务队列
function claimTask(PDO $pdo): ?array
{
    $pdo->beginTransaction();
    // 跳过正在被其他worker处理的任务
    $stmt = $pdo->query(
        "SELECT * FROM tasks WHERE status = 'pending'
         ORDER BY id LIMIT 1 FOR UPDATE SKIP LOCKED"
    );
    $task = $stmt->fetch();

    if ($task) {
        $pdo->prepare("UPDATE tasks SET status = 'processing' WHERE id = ?")
            ->execute([$task['id']]);
    }

    $pdo->commit();
    return $task ?: null;
}
```

## 乐观锁：版本号机制

```php
<?php
// 乐观锁：假设不会冲突，更新时检查版本
// 适合读多写少的场景

class OptimisticLock
{
    public function __construct(private PDO $pdo) {}

    public function updateWithLock(string $table, int $id, array $data, int $version): bool
    {
        $sets = [];
        $params = [];
        foreach ($data as $key => $value) {
            $sets[] = "{$key} = :{$key}";
            $params[":{$key}"] = $value;
        }

        // version+1 作为更新条件
        $sets[] = 'version = version + 1';
        $params[':id'] = $id;
        $params[':version'] = $version;

        $sql = "UPDATE {$table} SET " . implode(', ', $sets) . " WHERE id = :id AND version = :version";
        $stmt = $this->pdo->prepare($sql);
        $stmt->execute($params);

        if ($stmt->rowCount() === 0) {
            throw new RuntimeException('数据已被其他用户修改，请刷新后重试');
        }

        return true;
    }
}

// 使用
$product = $pdo->query("SELECT * FROM products WHERE id = 1")->fetch();
// 用户在页面上编辑...
// 提交时带上版本号
$locker = new OptimisticLock($pdo);
$locker->updateWithLock('products', 1, [
    'name' => '新名称',
    'price' => 99.9,
], $product['version']);
// 如果version不匹配（已被其他人修改），rowCount=0，抛出异常
```

### 悲观锁 vs 乐观锁选择

| 维度 | 悲观锁 | 乐观锁 |
|------|--------|--------|
| 冲突假设 | 一定会冲突 | 很少冲突 |
| 加锁时机 | 读取时 | 更新时 |
| 性能 | 有锁等待开销 | 无锁开销 |
| 适用场景 | 写多、高并发库存 | 读多写少、表单编辑 |
| 实现复杂度 | 低（SQL即可） | 中（需版本号字段） |
| 死锁风险 | 有 | 无 |

## 面试常见追问

**Q: 事务中发生异常但忘记rollBack会怎样？**
A: 脚本结束时PHP会关闭连接，MySQL自动回滚未提交的事务。但在PHP-FPM长连接场景下，连接可能被下一个请求复用，导致事务泄漏。最佳实践：使用`try/finally`确保`rollBack`在`beginTransaction`之后一定会执行。

**Q: SELECT FOR UPDATE和UPDATE直接加锁有什么区别？**
A: `SELECT FOR UPDATE`是先读取后加锁，可以在更新前做业务校验（如检查余额是否足够）。直接`UPDATE`是盲写，无法在更新前做条件判断。另外`SELECT FOR UPDATE`可以锁定多行，控制更精细。

**Q: SKIP LOCKED在任务队列中有什么优势？**
A: 传统做法是`SELECT FOR UPDATE`获取最早的任务，但多个worker会竞争同一行导致锁等待。`SKIP LOCKED`让每个worker直接跳过被锁定的任务，获取下一个未被锁定的任务，实现无竞争的并行消费。
