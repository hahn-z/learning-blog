# PHP内存管理与垃圾回收

理解PHP的内存管理机制，是排查内存泄漏、优化长运行脚本（队列Worker、CLI工具）的基础。

## 引用计数基础

PHP使用引用计数（reference counting）管理变量生命周期。每个zval（PHP变量底层结构）维护一个`refcount`和`is_ref`标志。

```php
<?php
// 查看引用计数
$a = "hello";
xdebug_debug_zval('a');  // a: (refcount=1, is_ref=0)='hello'

$b = $a;  // 写时复制（Copy-on-Write），共享同一个zval
xdebug_debug_zval('a');  // a: (refcount=2, is_ref=0)='hello'

$b = "world";  // 修改$b，触发COW，$a和$b分离
xdebug_debug_zval('a');  // a: (refcount=1, is_ref=0)='hello'

unset($b);  // refcount-1，为0时释放内存
```

### PHP 7的zval优化

PHP 7之前zval是堆分配的，即使整数也需两次内存分配。PHP 7将zval改为栈上值类型，简单类型（int/float/bool/null）不再需要引用计数：

```php
<?php
// PHP 7+: 整数、浮点数、布尔值不使用引用计数
$a = 42;     // zval直接存值在栈上，无refcount
$b = $a;     // 直接复制值，无共享

// 字符串、数组、对象仍然使用引用计数
$arr = [1, 2, 3];  // zval指向堆上的HashTable，refcount=1
$arr2 = $arr;       // refcount=2，共享HashTable
$arr2[] = 4;        // COW，分离为独立副本
```

## 循环引用问题

引用计数无法处理循环引用——两个变量互相引用，refcount永远不会降到0：

```php
<?php
class Node {
    public ?Node $parent = null;
    public array $children = [];
}

$root = new Node();
$child = new Node();

// 循环引用：root → child → root
$child->parent = $root;
$root->children[] = $child;

// unset后两个对象的refcount都不为0
unset($root);
unset($child);
// Node($root)的refcount: 1（被$child->parent引用）
// Node($child)的refcount: 1（被$root->children引用）
// → 内存泄漏！
```

## PHP的垃圾回收器

PHP 5.3引入了垃圾回收器（GC）专门处理循环引用。核心机制是**根缓冲区**+**模拟减引用计数**。

### GC工作流程

1. **根缓冲区**：PHP维护一个大小为10000的缓冲区，记录可能的"垃圾根"（zval refcount减少但未被销毁的变量）
2. **当缓冲区满**（10000个根）时触发GC
3. **模拟减**：对每个根及其子节点refcount减1
4. **回收**：refcount减为0的节点就是循环引用垃圾，回收之

```php
<?php
// 手动触发垃圾回收
$collected = gc_collect_cycles();
echo "回收了 $collected 个循环引用对象\n";

// 开启/关闭GC
gc_enable();
gc_disable();

// 检查GC状态
var_dump(gc_enabled()); // true/false

// 查看GC统计
$stats = gc_status();
print_r($stats);
// [
//     'runs' => 5,           // GC运行次数
//     'collected' => 1203,   // 总回收对象数
//     'threshold' => 10000,  // 根缓冲区大小
//     'roots' => 42,         // 当前缓冲区中的根数量
// ]
```

## 内存泄漏排查

### memory_get_usage追踪

```php
<?php
// 实时监控内存使用
function logMemory(string $label): void {
    $real = memory_get_usage(true);   // 实际分配的内存（含未使用部分）
    $used = memory_get_usage(false);  // PHP实际使用的内存
    $peak = memory_get_peak_usage(false);
    
    error_log(sprintf("[%s] Used: %.2fMB | Real: %.2fMB | Peak: %.2fMB",
        $label, $used / 1024 / 1024, $real / 1024 / 1024, $peak / 1024 / 1024));
}

// 长运行脚本中定期检查
class MemoryGuard {
    private int $limitBytes;
    private int $lastCheck = 0;
    
    public function __construct(int $limitMB = 128) {
        $this->limitBytes = $limitMB * 1024 * 1024;
    }
    
    public function check(): void {
        $now = memory_get_usage(true);
        if ($now > $this->limitBytes) {
            $collected = gc_collect_cycles();
            $after = memory_get_usage(true);
            error_log(sprintf(
                "MemoryGuard: %.1fMB > %.1fMB limit, GC collected %d objects, now %.1fMB",
                $now / 1024 / 1024, $this->limitBytes / 1024 / 1024,
                $collected, $after / 1024 / 1024
            ));
            
            // GC后仍超限，考虑重启worker
            if ($after > $this->limitBytes * 0.9) {
                error_log("MemoryGuard: still over 90% limit after GC, worker should restart");
            }
        }
    }
}
```

### 常见内存泄漏模式

```php
<?php
// 1. 静态属性累积
class Cache {
    private static array $data = []; // 只增不减
    public static function set(string $key, mixed $value): void {
        self::$data[$key] = $value; // 永远不清理
    }
}

// 2. 事件监听器未移除
class EventBus {
    private array $listeners = [];
    public function on(string $event, callable $fn): void {
        $this->listeners[$event][] = $fn; // 闭包可能捕获大量上下文
    }
}

// 3. 长运行循环中的临时对象
function processAll(array $items): void {
    foreach ($items as $item) {
        $result = heavyProcess($item);
        saveResult($result);
        // $result不会立即释放，因为还在foreach的作用域内
        unset($result); // 手动释放有帮助
    }
    gc_collect_cycles(); // 每批处理完触发GC
}

// 4. 循环引用（最常见的隐蔽泄漏）
class TreeNode {
    public ?TreeNode $parent = null;
    public array $children = [];
    
    public function addChild(TreeNode $child): void {
        $child->parent = $this;
        $this->children[] = $child;
    }
    
    // PHP 8.0+ 析构函数中断开引用
    public function __destruct() {
        $this->parent = null;
        $this->children = [];
    }
}
```

## 面试常见追问

**Q: gc_collect_cycles应该在什么时候调用？**
A: 长运行脚本（队列Worker）在处理完一批任务后调用。普通Web请求通常不需要手动调用——请求结束时会自动释放所有内存。

**Q: 为什么PHP Web请求通常不用担心内存泄漏？**
A: PHP-FPM每个请求结束后销毁整个请求上下文，所有变量被释放。内存泄漏只在CLI长运行脚本中有影响。

**Q: PHP 7的zval优化带来了多少性能提升？**
A: 简单类型（int/float/bool）的赋值和传递不再涉及堆操作和引用计数。实际基准测试中，纯数据操作场景内存使用减少约50%，速度提升10-20%。

**Q: WeakMap能解决循环引用吗？**
A: PHP 8.0引入的WeakMap/WeakReference可以让引用不计入refcount。适合缓存、观察者模式等场景，但不适合所有循环引用——父子关系中parent引用适合用WeakReference，children引用仍需要强引用。
