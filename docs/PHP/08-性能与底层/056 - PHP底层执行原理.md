---# PHP底层执行原理

理解PHP从源代码到执行的完整流程，能帮助你写出更高性能的代码，也能在面试中展示深度。

## 编译管线总览

```
PHP源代码
   ↓ 词法分析 (Lexer/re2c)
Tokens（词法单元流）
   ↓ 语法分析 (Parser/bison)
AST（抽象语法树）
   ↓ 编译器 (Compiler)
Opcodes（操作码指令）
   ↓ Zend虚拟机 (ZendVM)
执行结果
```

### 第一阶段：词法分析（Lexing）

词法分析器将源代码字符串分割为Token流。PHP使用re2c工具生成词法分析器：

```php
<?php
// 源代码
$a = 1 + 2;

// 词法分析后的Token流（可用token_get_all查看）
$tokens = token_get_all('<?php $a = 1 + 2;');
/*
[
    [T_OPEN_TAG,    '<?php '],
    [T_VARIABLE,    '$a'],
    [T_WHITESPACE,  ' '],
    '=',                     // 单字符token
    [T_WHITESPACE,  ' '],
    [T_LNUMBER,     '1'],
    [T_WHITESPACE,  ' '],
    '+',
    [T_WHITESPACE,  ' '],
    [T_LNUMBER,     '2'],
    ';',
]
*/
```

### 第二阶段：语法分析（Parsing）

语法分析器根据PHP语法规则（BNF范式），将Token流构建为AST（抽象语法树）。PHP使用bison生成语法分析器。

```
AST结构（简化）:
Assign(
    var: Variable('$a'),
    expr: BinaryOp(
        op: '+',
        left: Literal(1),
        right: Literal(2)
    )
)
```

**AST的意义**：PHP 7引入了AST作为独立编译阶段，使得编译器和优化器可以基于树结构做分析和变换，而不是直接从Token生成opcode。

### 第三阶段：编译（Compilation）

编译器遍历AST，生成opcode指令数组。每条opcode包含：

- **opcode类型**：操作码（ASSIGN、ADD、ECHO、FETCH_*等）
- **op1**：操作数1
- **op2**：操作数2
- **result**：结果操作数
- **extended_value**：扩展信息

```
$a = 1 + 2; 生成的opcode:
  ASSIGN_OP  $a, 1+2  (编译期常量折叠后)
  ↓ 实际上编译器优化后直接:
  ASSIGN  $a, 3
```

### 第四阶段：执行（ZendVM）

Zend虚拟机是一个栈式虚拟机，逐条执行opcode：

```php
<?php
// 用vld扩展查看opcode（安装: pecl install vld）
// php -d vld.active=1 -d vld.execute=0 test.php

// 代码: function add($a, $ b) { return $a + $b; } echo add(1, 2);

/*
生成的opcode（简化）:
1. INIT_FCALL 'add'
2. SEND_VAL 1
3. SEND_VAL 2
4. DO_FCALL
5. ECHO result
*/
```

## 常见opcode类型

| opcode | 含义 | 示例 |
|--------|------|------|
| ASSIGN | 赋值 | `$a = 1` |
| ASSIGN_ADD | 加法赋值 | `$a += 1` |
| ADD/SUB/MUL/DIV | 算术运算 | `$a + $b` |
| CONCAT | 字符串连接 | `$a . $b` |
| ECHO | 输出 | `echo $a` |
| FETCH_R/IS/W | 读取/isset/写入变量 | `$arr['key']` |
| INIT_FCALL | 初始化函数调用 | `func()` |
| DO_FCALL | 执行函数调用 | - |
| JMP/JMPZ/JMPNZ | 条件/无条件跳转 | `if/while/for` |
| RETURN | 返回 | `return $val` |
| SEND_VAL/SEND_VAR | 传递参数 | `func($val)` |
| RECV | 接收参数 | 函数定义中的参数 |

## PHP 7性能提升原理

PHP 7相比PHP 5性能提升约2倍，核心优化：

### 1. zval从堆分配改为栈分配

```c
// PHP 5: zval总是堆分配，两次内存分配
zval *val = ALLOC_ZVAL();   // 分配zval结构
val->value.str = estrndup() // 分配字符串值

// PHP 7: zval是栈上值类型，嵌入数据
zval val;
ZVAL_LONG(&val, 42);  // 直接在栈上存整数，无额外分配
```

### 2. HashTable重构

PHP 5的HashTable用双向链表+桶数组，内存碎片多，缓存不友好。PHP 7改为连续内存的紧凑数组，CPU缓存命中率高。

### 3. 函数调用优化

PHP 7使用寄存器传递参数（zend_execute_data栈帧），减少内存间接寻址。PHP 5通过HashTable传递。

### 4. AST中间表示

PHP 5直接从Token生成opcode，编译逻辑混乱。PHP 7引入AST使得编译过程更清晰，也更容易做编译期优化（如常量折叠、死代码消除）。

```bash
# 安装vld扩展
pecl install vld

# 查看opcode
php -d vld.active=1 -d vld.execute=0 script.php

# 输出示例:
# function foo($x) { return $x * 2; }

#   RECV    1          ; 接收参数$x
#   MUL     ~0, !0, 2  ; $x * 2 → 临时变量~0
#   RETURN  ~0         ; 返回结果

# echo foo(3):
#   INIT_FCALL 'foo'
#   SEND_VAL 3
#   DO_FCALL  $1
#   ECHO      $1
```

## 面试常见追问

**Q: PHP是编译型还是解释型语言？**
A: 两者兼有。PHP先编译为opcode（编译阶段），再由ZendVM逐条执行opcode（解释执行）。OPcache缓存了编译结果，使得重复请求跳过编译阶段。JIT（PHP 8）进一步将热点opcode编译为机器码。

**Q: 为什么PHP每请求都要重新编译？**
A: PHP的设计是"共享不共享"——每个请求独立的进程/线程，无全局状态共享。OPcache通过共享内存解决了这个问题，所有进程共享同一份编译结果。

**Q: opcode数量和性能的关系？**
A: opcode越多执行越慢。减少opcode的方法：减少不必要的函数调用、避免动态变量访问、用`isset`代替`array_key_exists`、常量直接使用而非函数调用。

**Q: re2c和bison是什么？**
A: re2c是词法分析器生成器，将正则规则转换为高效C代码。bison是语法分析器生成器，将BNF文法规则转换为LALR(1)解析器。PHP的编译前端由这两个工具生成。
