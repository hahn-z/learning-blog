# PHP性能分析工具链

性能优化的第一步不是猜，而是测量。掌握正确的工具链，才能精准定位瓶颈。

## XHProf：PHP层级性能分析器

### 安装与配置

```bash
# PHP 8.x 安装（tideways fork版本，兼容PHP 8）
pecl install tideways_xhprof

# php.ini
extension=tideways_xhprof.so
; 不全局开启，按需在代码中开启
```

### 按需采样

```php
<?php
// 在入口文件最顶部开启
tideways_xhprof_enable(TIDEWAYS_XHPROF_FLAGS_CPU | TIDEWAYS_XHPROF_FLAGS_MEMORY);

// ... 应用正常执行 ...

// 请求结束时收集数据
register_shutdown_function(function () {
    $data = tideways_xhprof_disable();
    
    $dir = '/var/log/xhprof';
    if (!is_dir($dir)) mkdir($dir, 0755, true);
    
    // 保存为文件（后续用UI查看）
    $filename = sprintf('%s/%s.%s.xhprof',
        $dir,
        date('Y-m-d_His'),
        uniqid()
    );
    file_put_contents($filename, serialize($data));
});
```

### 采样率控制（生产环境安全）

```php
<?php
// 生产环境只采样1%的请求
if (random_int(1, 100) === 1) {
    tideways_xhprof_enable(TIDEWAYS_XHPROF_FLAGS_CPU | TIDEWAYS_XHPROF_FLAGS_MEMORY);
    
    register_shutdown_function(function () {
        $data = tideways_xhprof_disable();
        // 发送到时间序列数据库或XHProf UI
        saveProfile($data);
    });
}
```

### XHProf UI查看报告

```bash
# 安装XHGui（现代化的XHProf查看器）
git clone https://github.com/perftools/xhgui.git
cd xhgui
composer install

# 导入profile数据
php import.php /var/log/xhprof/2026-05-31_*.xhprof
```

XHProf输出的关键指标：
- **Wall Time**：实际经过时间（含I/O等待）
- **CPU Time**：纯CPU计算时间
- **Memory**：内存变化量
- **Calls**：调用次数
- **Excl. Time**：排除子函数后的自身耗时

## Blackfire.io：专业级分析器

```bash
# 安装agent和probe
curl -sSL https://packages.blackfire.io/gpg.key | sudo apt-key add -
echo "deb http://packages.blackfire.io/deb any main" | sudo tee /etc/apt/sources.list.d/blackfire.list
sudo apt update && sudo apt install blackfire-agent blackfire-php

# 配置凭证
blackfire config --client-id=xxx --client-token=xxx

# CLI分析
blackfire run php my-script.php

# 分析URL
blackfire curl https://api.example.com/users

# 在代码中嵌入
# Blackfire自动检测并采样，无需修改代码
```

Blackfire的优势：
- 不需要采样率控制，按需触发
- 时间线视图（SQL查询、HTTP调用、函数调用时序）
- 与CI集成，性能回归自动报警
- 调用图可视化

## strace：系统调用追踪

当PHP性能问题出在系统层面（网络、文件I/O、锁）时，strace最有用：

```bash
# 追踪PHP-FPM worker的系统调用
# 1. 找到worker PID
pid=$(pgrep -f "php-fpm: pool www" | head -1)

# 2. 追踪
sudo strace -p $pid -T -f -e trace=read,write,connect,poll,select,epoll_wait

# -T: 显示每个系统调用耗时
# -f: 追踪子进程
# -e trace=: 只追踪指定的系统调用

# 常用过滤
# 只看网络相关
sudo strace -p $pid -T -e trace=network

# 只看文件操作
sudo strace -p $pid -T -e trace=file

# 统计模式（汇总每个系统调用的次数和耗时）
sudo strace -p $pid -c
```

### strace输出解读

```
connect(3, {sa_family=AF_INET, sin_port=htons(3306), ...}, 16) = 0 <0.001234>
# 连接MySQL耗时1.234ms

poll([{fd=3, events=POLLIN|POLLERR|POLLHUP}], 1, 60000) = 1 ([{fd=3, revents=POLLIN}]) <0.045678>
# 等待MySQL响应耗时45.678ms → SQL查询慢

write(5, "SELECT * FROM users WHERE...", 48) = 48 <0.000012>
read(5, "...", 8192)                    = 8192 <0.000234>
```

## perf + 火焰图

当需要看到CPU时间花在哪里时，火焰图是最直观的工具：

```bash
# 1. 采样CPU性能数据（60秒）
sudo perf record -F 99 -p $(pgrep -f "php-fpm: pool www" | tr '\n' ',') -g -- sleep 60

# 2. 生成火焰图
git clone https://github.com/brendangregg/FlameGraph.git
sudo perf script | FlameGraph/stackcollapse-perf.pl | FlameGraph/flamegraph.pl > flamegraph.svg

# 3. 或者用PHP专用工具（更好的函数名解析）
# 安装 phpspy（低开销PHP采样器）
git clone https://github.com/adsr/phpspy.git
cd phpspy && make

# 采样所有PHP-FPM worker
sudo ./phpspy -p $(pgrep -f "php-fpm: pool www" | head -1) -r 100

# 生成火焰图
sudo ./phpspy -p $(pgrep -f "php-fpm: pool www" | head -1) \
  | FlameGraph/flamegraph.pl > php-flamegraph.svg
```

### 火焰图阅读方法

- **x轴**：函数调用栈的采样比例（不是时间顺序）
- **y轴**：调用栈深度（从下往上）
- **宽度**：CPU时间占比，越宽越耗时
- **颜色**：无特殊含义，随机色区分不同函数

## 工具选择指南

| 问题类型 | 推荐工具 | 粒度 |
|----------|----------|------|
| 哪个函数慢 | XHProf/XHGui | 函数级 |
| SQL/HTTP调用耗时 | Blackfire | 调用级+时间线 |
| 系统调用阻塞 | strace | syscall级 |
| CPU密集计算 | perf+火焰图 | 全栈 |
| 内存泄漏 | memory_get_usage + gc_status | PHP级 |

## 面试常见追问

**Q: XHProf和Blackfire有什么区别？**
A: XHProf是免费开源的，通过函数钩子实现，有2-5%的性能开销。Blackfire是商业产品，使用独立的agent进程，开销更低（<1%），UI更强大，支持CI集成和性能回归检测。

**Q: 生产环境能开性能分析吗？**
A: XHProf可以采样模式（1%概率）安全运行。Blackfire是按需触发（手动或CI触发），生产安全。perf和strace需要sudo权限且有一定开销，建议只在排查问题时短时间使用。

**Q: 火焰图中看到很宽的`__construct`怎么办？**
A: 不要只看函数名，看调用栈上方的业务函数。`__construct`可能是某个Service初始化时触发的，真正耗时的是构造函数中的I/O操作（数据库连接、文件读取）。
