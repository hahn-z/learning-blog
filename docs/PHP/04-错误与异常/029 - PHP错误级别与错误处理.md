---# PHP错误级别与错误处理

## 错误级别体系

PHP定义了16种错误级别，从致命错误到废弃通知，构成了一个完整的错误分层体系。

### 核心错误级别一览

| 级别 | 常量 | 值 | 是否可捕获 | 典型场景 |
|------|------|-----|-----------|---------|
| 致命错误 | `E_ERROR` | 1 | 否 | 内存耗尽、调用未定义函数 |
| 警告 | `E_WARNING` | 2 | 是 | include文件不存在、参数类型错误 |
| 解析错误 | `E_PARSE` | 4 | 否 | 语法错误 |
| 通知 | `E_NOTICE` | 8 | 是 | 未定义变量 |
| 废弃通知 | `E_DEPRECATED` | 8192 | 是 | 使用废弃函数如`mysql_connect` |
| 严格模式 | `E_STRICT` | 2048 | 是 | 不兼容的方法签名 |

`E_ALL`（值8191，PHP8.4中为`E_ALL = ~0`）是所有错误级别的位掩码组合。

### 底层机制：错误如何产生

PHP引擎在执行过程中遇到问题时，会调用`zend_error()`函数。该函数根据错误级别决定行为：

1. **`E_ERROR`/`E_PARSE`/`E_CORE_ERROR`** → 调用`zend_bailout()`进行长跳转（longjmp），直接终止脚本
2. **可恢复错误** → 先检查是否有用户注册的错误处理器，有则调用，无则走默认逻辑（输出到stderr/web SAPI的错误日志）

```php
// 看看当前环境的错误报告配置
echo error_reporting(); // 输出当前错误级别掩码，如 32767 = E_ALL

// 推荐开发环境配置
error_reporting(E_ALL);
ini_set('display_errors', '1');
ini_set('log_errors', '1');
ini_set('error_log', __DIR__ . '/logs/php-error.log');

// 生产环境：不显示，只记录
error_reporting(E_ALL & ~E_DEPRECATED & ~E_STRICT);
ini_set('display_errors', '0');
```

## set_error_handler：拦截用户级错误

`set_error_handler()`可以捕获除`E_ERROR`、`E_PARSE`、`E_CORE_ERROR`等致命错误之外的所有错误。

```php
<?php
// 自定义错误处理器
set_error_handler(function (int $errno, string $errstr, string $errfile, int $errline): bool {
    $levels = [
        E_WARNING => 'WARNING',
        E_NOTICE  => 'NOTICE',
        E_DEPRECATED => 'DEPRECATED',
        E_USER_WARNING => 'USER_WARNING',
    ];

    $level = $levels[$errno] ?? "UNKNOWN($errno)";

    // 记录到日志（带调用栈）
    error_log(sprintf(
        "[%s] %s: %s in %s:%d\n",
        date('Y-m-d H:i:s'),
        $level,
        $errstr,
        $errfile,
        $errline
    ));

    // 返回true表示已处理，不再走PHP默认处理
    // 返回false则继续走默认处理
    return true;
});

// 触发一些错误来测试
echo $undefinedVar;           // E_NOTICE → 被捕获
strlen();                     // E_WARNING → 被捕获
mysql_connect('localhost');   // E_DEPRECATED → 被捕获（如果PHP版本还支持）
```

**关键细节：** 错误处理器内部不能再触发同类型错误，否则PHP会直接走默认处理，避免无限递归。

### 将错误转换为异常

一个常见模式是将用户级错误转为`ErrorException`，这样可以被`try/catch`捕获：

```php
<?php
set_error_handler(function (int $errno, string $errstr, string $errfile, int $errline) {
    // error_reporting()为0表示@抑制符，不转换
    if (!(error_reporting() & $errno)) {
        return false;
    }
    throw new ErrorException($errstr, 0, $errno, $errfile, $errline);
});

try {
    $result = file_get_contents('/nonexistent/file.txt');
} catch (ErrorException $e) {
    echo "捕获到错误: " . $e->getMessage(); // 正常捕获WARNING
}
```

这个技巧在PHP8+中尤其有价值，因为很多之前的`E_WARNING`已经升级为`TypeError`/`ValueError`等异常。

## set_exception_handler：最后的防线

当异常没有被任何`try/catch`捕获时，PHP会调用注册的异常处理器，之后脚本**必然终止**。

```php
<?php
set_exception_handler(function (Throwable $e): void {
    // 记录完整异常信息
    error_log(sprintf(
        "Uncaught %s: %s in %s:%d\nStack trace:\n%s",
        get_class($e),
        $e->getMessage(),
        $e->getFile(),
        $e->getLine(),
        $e->getTraceAsString()
    ));

    // 生产环境：返回友好的JSON错误响应
    if (php_sapi_name() !== 'cli') {
        http_response_code(500);
        header('Content-Type: application/json');
        echo json_encode([
            'error' => 'Internal Server Error',
            'message' => ini_get('display_errors') ? $e->getMessage() : '服务异常，请稍后重试',
        ]);
    }
});

// 任何未捕获的异常都会走到这里
throw new RuntimeException("数据库连接失败");
echo "这行永远不会执行";
```

## error_reporting配置详解

配置有三个层面：

```php
<?php
// 1. php.ini（全局配置）
// error_reporting = E_ALL
// display_errors = Off

// 2. 运行时配置（脚本内）
error_reporting(E_ALL & ~E_NOTICE); // 除了NOTICE都报告

// 3. @错误抑制符
// @会在该表达式执行期间将error_reporting设为0
// 注意：PHP8.0+中@不再抑制E_ERROR/E_CORE_ERROR等致命错误

$value = @file_get_contents('maybe-missing.txt');
// 等价于在表达式前后临时设置error_reporting(0)

// 判断是否被@抑制（在error_handler中）
set_error_handler(function (int $errno, string $errstr, string $errfile, int $errline): bool {
    if (error_reporting() === 0) {
        return false; // 被@抑制，走默认处理（即静默）
    }
    // 正常处理
    return true;
});
```

### 位运算控制错误级别

```php
<?php
// 常用组合
error_reporting(E_ALL);                          // 报告所有错误
error_reporting(E_ALL & ~E_NOTICE);              // 排除NOTICE
error_reporting(E_ALL & ~E_NOTICE & ~E_DEPRECATED); // 排除NOTICE和DEPRECATED
error_reporting(E_ERROR | E_WARNING | E_PARSE);  // 只报告严重错误

// 动态检查某个级别是否开启
if (error_reporting() & E_NOTICE) {
    echo "NOTICE级别已开启";
}
```

## 完整的错误处理最佳实践

```php
<?php
// app_error_handler.php — 生产级错误处理方案

class ErrorHandler
{
    public static function register(): void
    {
        error_reporting(E_ALL);
        ini_set('display_errors', APP_DEBUG ? '1' : '0');
        ini_set('log_errors', '1');

        set_error_handler([self::class, 'handleError']);
        set_exception_handler([self::class, 'handleException']);
        register_shutdown_function([self::class, 'handleShutdown']);
    }

    public static function handleError(int $errno, string $errstr, string $errfile, int $errline): bool
    {
        if (!(error_reporting() & $errno)) {
            return false;
        }
        throw new ErrorException($errstr, 0, $errno, $errfile, $errline);
    }

    public static function handleException(Throwable $e): void
    {
        error_log(self::formatException($e));

        if (!headers_sent()) {
            http_response_code(500);
            header('Content-Type: application/json');
        }

        echo json_encode([
            'error' => true,
            'message' => APP_DEBUG ? $e->getMessage() : '服务器内部错误',
            'trace' => APP_DEBUG ? $e->getTraceAsString() : null,
        ]);
    }

    public static function handleShutdown(): void
    {
        $error = error_get_last();
        if ($error && in_array($error['type'], [E_ERROR, E_PARSE, E_CORE_ERROR, E_COMPILE_ERROR])) {
            self::handleException(new ErrorException(
                $error['message'], 0, $error['type'], $error['file'], $error['line']
            ));
        }
    }

    private static function formatException(Throwable $e): string
    {
        return sprintf(
            "[%s] %s: %s in %s:%d\n%s",
            date('c'), get_class($e), $e->getMessage(),
            $e->getFile(), $e->getLine(), $e->getTraceAsString()
        );
    }
}

// 使用
define('APP_DEBUG', getenv('APP_DEBUG') === 'true');
ErrorHandler::register();
```

`register_shutdown_function`配合`error_get_last()`是捕获致命错误（`E_ERROR`）的唯一方式，因为致命错误无法被`set_error_handler`拦截。

## 面试常见追问

**Q: E_ERROR和Exception有什么区别？**
A: `E_ERROR`是PHP引擎级别的错误，无法被`try/catch`捕获，脚本直接终止。Exception是语言层面的异常机制，可以被捕获和恢复。PHP7+中很多`E_ERROR`场景（如类型错误）已改为抛出`TypeError`，可被捕获。两者的根本区别：错误是不可恢复的，异常是可以恢复的。

**Q: @符号有什么性能影响？**
A: `@`会在表达式执行前将error_reporting设为0，执行后恢复。PHP8.0之前这涉及ini设置的修改，有一定开销。PHP8.0+优化了这个过程，使用`EG(error_reporting)`快速切换，性能影响已很小。但最佳实践是尽量不用`@`，而是通过条件检查避免错误。

**Q: 如何在生产环境中做到既不暴露错误信息又不丢失错误信息？**
A: `display_errors=Off`关闭显示，`log_errors=On`开启日志记录，同时配置`error_log`指向具体文件。配合`set_exception_handler`和`register_shutdown_function`确保所有错误都被记录。
