# PHP自定义异常与异常链

## 为什么要自定义异常

PHP内置的`Exception`和`RuntimeException`太泛，无法区分不同的业务场景。自定义异常的核心价值是**让catch方知道发生了什么，而不仅仅是"出错了"**。

```php
<?php
// 不好的做法：所有错误都用一个Exception
throw new Exception('用户不存在');
throw new Exception('数据库连接失败');
throw new Exception('余额不足');

// catch方无法区分该重试还是该返回404
try {
    $result = $service->process();
} catch (Exception $e) {
    // 我该返回400？500？还是重试？
}

// 好的做法：用异常类型表达语义
throw new UserNotFoundException('用户不存在');     // → 返回404
throw new DatabaseConnectionException('连接失败'); // → 返回500，可重试
throw new InsufficientBalanceException('余额不足'); // → 返回400
```

## 自定义异常层级设计

### 分层架构

```
AppException (抽象基类)
├── BusinessException (业务异常 - 客户端错误 4xx)
│   ├── UserNotFoundException
│   ├── InvalidParameterException
│   ├── InsufficientBalanceException
│   ├── DuplicateResourceException
│   └── UnauthorizedException
└── SystemException (系统异常 - 服务端错误 5xx)
    ├── DatabaseException
    │   ├── ConnectionException
    │   └── QueryException
    ├── CacheException
    └── ExternalServiceException
        ├── PaymentGatewayException
        └── SmsServiceException
```

### 完整实现

```php
<?php
// 基类：所有自定义异常的祖先
abstract class AppException extends RuntimeException
{
    protected string $errorCode;    // 业务错误码，如 "USER_001"
    protected int $httpStatus;      // 对应的HTTP状态码

    public function __construct(
        string $message,
        string $errorCode = '',
        int $httpStatus = 500,
        ?Throwable $previous = null
    ) {
        $this->errorCode = $errorCode;
        $this->httpStatus = $httpStatus;
        parent::__construct($message, 0, $previous);
    }

    public function getErrorCode(): string { return $this->errorCode; }
    public function getHttpStatus(): int { return $this->httpStatus; }

    // 是否为业务异常（可预期）
    abstract public function isBusinessError(): bool;
}

// 业务异常基类
class BusinessException extends AppException
{
    public function __construct(
        string $message,
        string $errorCode = 'BIZ_ERROR',
        int $httpStatus = 400,
        ?Throwable $previous = null
    ) {
        parent::__construct($message, $errorCode, $httpStatus, $previous);
    }

    public function isBusinessError(): bool { return true; }
}

// 系统异常基类
class SystemException extends AppException
{
    public function __construct(
        string $message,
        string $errorCode = 'SYS_ERROR',
        int $httpStatus = 500,
        ?Throwable $previous = null
    ) {
        parent::__construct($message, $errorCode, $httpStatus, $previous);
    }

    public function isBusinessError(): bool { return false; }
}

// 具体业务异常
class UserNotFoundException extends BusinessException
{
    public function __construct(int $userId, ?Throwable $previous = null)
    {
        parent::__construct(
            "用户不存在: ID={$userId}",
            'USER_001',
            404,
            $previous
        );
    }
}

class InsufficientBalanceException extends BusinessException
{
    public function __construct(float $required, float $actual, ?Throwable $previous = null)
    {
        parent::__construct(
            "余额不足: 需要{$required}，实际{$actual}",
            'BIZ_002',
            400,
            $previous
        );
    }
}

// 具体系统异常
class DatabaseQueryException extends SystemException
{
    public function __construct(string $sql, string $error, ?Throwable $previous = null)
    {
        parent::__construct(
            "数据库查询失败: {$error} | SQL: {$sql}",
            'DB_002',
            500,
            $previous
        );
    }
}
```

### 统一异常处理器

```php
<?php
class ExceptionHandler
{
    public function handle(Throwable $e): void
    {
        if ($e instanceof AppException) {
            $this->handleAppException($e);
        } else {
            // 未预期的异常
            $this->handleUnknownException($e);
        }
    }

    private function handleAppException(AppException $e): void
    {
        http_response_code($e->getHttpStatus());

        $response = [
            'success' => false,
            'error_code' => $e->getErrorCode(),
            'message' => $e->getMessage(),
        ];

        // 系统异常需要记录完整堆栈
        if (!$e->isBusinessError()) {
            error_log($this->formatWithChain($e));
            $response['message'] = '系统异常，请稍后重试'; // 对外隐藏细节
        }

        echo json_encode($response, JSON_UNESCAPED_UNICODE);
    }

    private function formatWithChain(Throwable $e): string
    {
        $parts = [];
        $current = $e;
        while ($current !== null) {
            $parts[] = sprintf(
                "%s: %s in %s:%d",
                get_class($current),
                $current->getMessage(),
                $current->getFile(),
                $current->getLine()
            );
            $current = $current->getPrevious();
        }
        return "Exception Chain:\n  → " . implode("\n  → ", $parts);
    }
}
```

## 异常链：$previous机制

异常链允许一个异常包装另一个异常，保留原始错误的完整上下文。

```php
<?php
class PaymentService
{
    public function charge(int $userId, float $amount): string
    {
        try {
            $response = $this->callPaymentGateway($userId, $amount);
            return $response['transaction_id'];
        } catch (GuzzleException $e) {
            // 将HTTP异常包装为业务异常，$previous保留原始异常
            throw new ExternalServiceException(
                "支付网关调用失败: {$e->getMessage()}",
                'PAY_001',
                502,
                $e  // ← 这就是异常链
            );
        }
    }

    private function callPaymentGateway(int $userId, float $amount): array
    {
        // 模拟HTTP调用
        throw new \GuzzleHttp\Exception\ConnectException(
            'Connection refused',
            new \GuzzleHttp\Psr7\Request('POST', '/pay')
        );
    }
}

// 调用方可以追溯到最底层原因
try {
    $paymentService->charge(1, 99.9);
} catch (ExternalServiceException $e) {
    echo "业务层: " . $e->getMessage() . "\n";
    echo "根因: " . $e->getPrevious()->getMessage() . "\n";
    // 输出:
    // 业务层: 支付网关调用失败: Connection refused
    // 根因: Connection refused
}
```

### 异常链遍历工具

```php
<?php
function getRootCause(Throwable $e): Throwable
{
    while ($e->getPrevious() !== null) {
        $e = $e->getPrevious();
    }
    return $e;
}

function getExceptionChain(Throwable $e): array
{
    $chain = [];
    while ($e !== null) {
        $chain[] = [
            'class' => get_class($e),
            'message' => $e->getMessage(),
            'file' => $e->getFile() . ':' . $e->getLine(),
        ];
        $e = $e->getPrevious();
    }
    return $chain;
}
```

## 业务异常 vs 系统异常分离

这是异常设计的核心原则：

| 维度 | 业务异常 | 系统异常 |
|------|---------|---------|
| 可预期性 | 可预期，是正常业务流程的一部分 | 不可预期，是系统故障 |
| HTTP状态码 | 4xx | 5xx |
| 日志级别 | INFO/WARNING | ERROR/CRITICAL |
| 告警 | 不需要 | 需要 |
| 堆栈暴露 | 可以暴露给用户 | 绝不能暴露 |
| 重试 | 无意义 | 可能值得重试 |

```php
<?php
class OrderService
{
    public function createOrder(int $userId, array $items): Order
    {
        // 业务校验 → 抛业务异常
        $user = $this->userRepository->find($userId)
            ?? throw new UserNotFoundException($userId);

        if (empty($items)) {
            throw new InvalidParameterException('商品列表不能为空', 'ORD_001');
        }

        // 系统操作 → 抛系统异常
        try {
            $order = $this->orderRepository->save(
                new Order($userId, $items)
            );
        } catch (PDOException $e) {
            throw new DatabaseQueryException('INSERT INTO orders', $e->getMessage(), $e);
        }

        return $order;
    }
}
```

## 面试常见追问

**Q: 自定义异常应该继承Exception还是RuntimeException？**
A: 取决于异常的性质。`Exception`是检查型异常（调用方必须处理），`RuntimeException`是非检查型异常（可以不处理）。PHP没有强制检查机制，但语义上：业务可预期的异常（余额不足）用`RuntimeException`子类，需要强制处理的用`Exception`子类。实际项目中统一继承`RuntimeException`更常见。

**Q: 异常链会不会导致内存问题？**
A: 理论上如果循环引用（A的previous是B，B的previous是A），会造成内存泄漏。但PHP的异常链是单向链表，不存在这个问题。唯一需要注意的是长链：如果每次都包装新异常，链会越来越长。通常3-4层已经是极限。

**Q: 什么时候该用异常，什么时候该用错误码（返回值）？**
A: 核心判断标准是"这个结果是调用方预期内的吗"。预期内的结果用返回值（如`User::find()`返回`null`），意外情况用异常（如数据库连接断开）。另一个角度：如果你需要在多层调用中跳过中间层直接处理，用异常更合适。
