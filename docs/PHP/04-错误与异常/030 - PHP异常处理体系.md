---# PHP异常处理体系

## 异常层次结构

PHP7开始建立了完整的异常层次结构，顶层接口是`Throwable`：

```
Throwable (interface)
├── Error (class)
│   ├── TypeError
│   ├── ArgumentCountError
│   ├── ArithmeticError
│   │   └── DivisionByZeroError
│   ├── AssertionError
│   └── ParseError
└── Exception (class)
    ├── RuntimeException
    │   ├── OutOfBoundsException
    │   ├── OverflowException
    │   ├── UnderflowException
    │   └── UnexpectedValueException
    ├── LogicException
    │   ├── BadFunctionCallException
    │   │   └── BadMethodCallException
    │   ├── DomainException
    │   └── InvalidArgumentException
    └── ErrorException
```

**关键区别：** `Error`是引擎级错误（如类型错误），`Exception`是应用级异常。两者都实现了`Throwable`接口，可以统一捕获。

```php
<?php
// PHP7+ 可以用Throwable捕获一切
try {
    // 任何可能抛出异常或错误的代码
    $result = 1 / 0;                // DivisionByZeroError
    strlen(null);                    // TypeError (PHP8)
    throw new Exception('手动异常');
} catch (Throwable $e) {
    echo get_class($e) . ": " . $e->getMessage();
}
```

## try/catch/finally完整机制

### 执行顺序

```php
<?php
function riskyOperation(int $divisor): int
{
    try {
        echo "1. 进入try\n";
        if ($divisor === 0) {
            throw new RuntimeException("除数不能为零");
        }
        $result = 100 / $divisor;
        echo "2. try正常执行\n";
        return $result;  // 注意：finally会在return之前执行
    } catch (RuntimeException $e) {
        echo "3. 进入catch: " . $e->getMessage() . "\n";
        return -1;
    } finally {
        // 无论try/catch是否抛异常、是否return，都会执行
        echo "4. finally始终执行\n";
    }
}

echo riskyOperation(0);
// 输出: 1. 进入try → 3. 进入catch → 4. finally始终执行 → -1
```

### finally的返回值覆盖陷阱

```php
<?php
function trickyReturn(): string
{
    try {
        return "from try";
    } finally {
        return "from finally"; // ⚠️ 这会覆盖try的返回值！
    }
}

echo trickyReturn(); // 输出 "from finally"
```

这是PHP的一个容易踩坑的特性：`finally`中的`return`会覆盖`try`或`catch`中的`return`。最佳实践是**永远不要在finally中使用return**。

### finally的正确用途

```php
<?php
// 资源清理的经典模式
function readFileSafely(string $path): string
{
    $handle = fopen($path, 'r');
    if ($handle === false) {
        throw new RuntimeException("无法打开文件: $path");
    }

    try {
        return stream_get_contents($handle);
    } finally {
        fclose($handle); // 无论是否异常，文件句柄都会被关闭
    }
}

// 数据库事务模式
function executeInTransaction(PDO $pdo, callable $callback): mixed
{
    $pdo->beginTransaction();
    try {
        $result = $callback($pdo);
        $pdo->commit();
        return $result;
    } finally {
        // 如果没有commit（异常导致跳过了），回滚
        if ($pdo->inTransaction()) {
            $pdo->rollBack();
        }
    }
}
```

## PHP8新特性：多重catch和throw表达式

### 多重catch（PHP 8.0+）

```php
<?php
// PHP7: 需要重复catch块或用共同的父类
try {
    $user = $userService->find($id);
} catch (InvalidArgumentException $e) {
    // 处理逻辑相同
    $this->logger->error($e->getMessage());
    throw new ApiBadRequestException($e->getMessage());
} catch (RuntimeException $e) {
    // 重复代码
    $this->logger->error($e->getMessage());
    throw new ApiBadRequestException($e->getMessage());
}

// PHP8: 用 | 合并多个异常类型
try {
    $user = $userService->find($id);
} catch (InvalidArgumentException | RuntimeException $e) {
    $this->logger->error($e->getMessage());
    throw new ApiBadRequestException($e->getMessage());
}
```

### throw表达式（PHP 8.0+）

`throw`从语句升级为表达式，可以出现在任何表达式能出现的位置：

```php
<?php
// 1. 三元运算符中使用
$value = $config['timeout']
    ?? throw new InvalidArgumentException('timeout配置缺失');

// 2. 箭头函数中直接抛出
$getOrFail = fn(string $key) => $_ENV[$key]
    ?? throw new RuntimeException("环境变量 {$key} 未设置");

$dbPassword = $getOrFail('DB_PASSWORD');

// 3. 短路逻辑中使用
$age > 0 || throw new InvalidArgumentException('年龄必须大于0');

// 4. Null合并运算符配合
$user = User::find($id) ?? throw new UserNotFoundException("用户{$id}不存在");

// 5. match表达式中使用
$format = match ($ext) {
    'json' => 'application/json',
    'xml'  => 'application/xml',
    default => throw new InvalidArgumentException("不支持的格式: {$ext}"),
};
```

## ErrorException：桥接错误与异常

`ErrorException`是将传统PHP错误转换为异常的桥梁：

```php
<?php
// ErrorException的构造函数
// public __construct(
//     string $message = "",
//     int $code = 0,
//     int $severity = E_ERROR,
//     ?string $filename = null,
//     ?int $line = null,
//     ?Throwable $previous = null
// )

// severity存储原始的E_XXX级别
set_error_handler(function ($errno, $errstr, $errfile, $errline) {
    throw new ErrorException($errstr, 0, $errno, $errfile, $errline);
});

try {
    echo $undefined; // E_NOTICE → ErrorException
} catch (ErrorException $e) {
    echo "严重级别: " . $e->getSeverity(); // 8 (E_NOTICE)
}
```

## Throwable接口方法

```php
<?php
interface Throwable extends Stringable
{
    public function getMessage(): string;          // 异常消息
    public function getCode(): int;                // 异常代码
    public function getFile(): string;             // 抛出文件
    public function getLine(): int;                // 抛出行号
    public function getTrace(): array;             // 调用栈数组
    public function getTraceAsString(): string;    // 调用栈字符串
    public function getPrevious(): ?Throwable;     // 前一个异常
    public function __toString(): string;          // 完整的字符串表示
}

// 实用：遍历异常链
function printExceptionChain(Throwable $e): void
{
    $depth = 0;
    while ($e !== null) {
        echo str_repeat("  ", $depth) . get_class($e) . ": {$e->getMessage()}\n";
        $e = $e->getPrevious();
        $depth++;
    }
}
```

## 面试常见追问

**Q: PHP7之前没有Error类，类型错误是怎么处理的？**
A: PHP5中类型不匹配只产生`E_RECOVERABLE_ERROR`，可以用`set_error_handler`捕获但脚本默认终止。PHP7引入`TypeError`（继承自`Error`）后，这些情况变成可捕获的异常，这是PHP7"一致性错误处理"的核心改进。

**Q: catch(Throwable)和catch(Exception)有什么区别？**
A: `Throwable`包括`Error`和`Exception`两个分支。`catch(Exception)`不会捕获`TypeError`、`DivisionByZeroError`等`Error`子类。如果你只想处理应用异常而让引擎错误走默认流程，用`Exception`；如果要统一兜底，用`Throwable`。

**Q: finally块中抛出异常会怎样？**
A: 如果try/catch中有异常正在抛出，finally中又抛了新异常，原来的异常会被覆盖（作为新异常的`$previous`）。这和Java的行为一致。所以finally中应该避免抛异常。

**Q: PHP8的throw表达式有什么实际价值？**
A: 最大的价值是配合`??`、`match`、箭头函数等使用，减少样板代码。之前需要在表达式之后写if+throw四行代码的场景，现在一行搞定。这在构造函数注入、配置读取等场景中极为常用。
