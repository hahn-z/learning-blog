# PHP日志系统设计

## PSR-3 Log接口

PSR-3定义了PHP日志组件的标准接口，所有主流日志库都实现了它：

```php
<?php
namespace Psr\Log;

interface LoggerInterface
{
    public function emergency(Stringable|string $message, array $context = []): void;
    public function alert(Stringable|string $message, array $context = []): void;
    public function critical(Stringable|string $message, array $context = []): void;
    public function error(Stringable|string $message, array $context = []): void;
    public function warning(Stringable|string $message, array $context = []): void;
    public function notice(Stringable|string $message, array $context = []): void;
    public function info(Stringable|string $message, array $context = []): void;
    public function debug(Stringable|string $message, array $context = []): void;
    public function log($level, Stringable|string $message, array $context = []): void;
}
```

### 日志级别选择指南

| 级别 | 场景 | 示例 |
|------|------|------|
| `DEBUG` | 开发调试信息 | SQL查询、请求参数 |
| `INFO` | 正常业务流程 | 用户登录、订单创建 |
| `NOTICE` | 正常但值得注意 | 慢查询、降级处理 |
| `WARNING` | 潜在问题 | 令牌即将过期、磁盘空间低 |
| `ERROR` | 运行时错误 | 第三方API调用失败 |
| `CRITICAL` | 严重错误 | 数据库不可用 |
| `ALERT` | 必须立即处理 | 支付系统异常 |
| `EMERGENCY` | 系统不可用 | 全站宕机 |

### PSR-3的context机制

```php
<?php
// 不要拼接字符串
$logger->info("用户 {$userId} 登录成功，IP: {$ip}");

// 用context传递结构化数据
$logger->info('用户登录成功', [
    'user_id' => $userId,
    'ip' => $ip,
    'user_agent' => $request->getHeaderLine('User-Agent'),
]);

// context支持占位符
$logger->info('用户 {user_id} 从 {ip} 登录', [
    'user_id' => $userId,
    'ip' => $ip,
]);
// 输出: 用户 12345 从 192.168.1.1 登录
```

## Monolog实战

Monolog是PHP生态中最强大的日志库，也是Laravel/Symfony的默认选择。

### 架构：Handler + Formatter + Processor

```
Logger
  ├── Processor[] → 在日志记录前添加额外信息（如请求ID、内存使用）
  ├── Handler[]   → 决定日志写到哪里（文件、数据库、Slack）
  │   └── Formatter → 决定日志的格式（JSON、文本、HTML）
  └── 每条日志经过所有Processor处理后，分发给匹配级别的Handler
```

### 基础配置

```php
<?php
require 'vendor/autoload.php';

use Monolog\Logger;
use Monolog\Handler\StreamHandler;
use Monolog\Handler\RotatingFileHandler;
use Monolog\Handler\NullHandler;
use Monolog\Formatter\JsonFormatter;
use Monolog\Formatter\LineFormatter;

// 创建日志通道
$logger = new Logger('app');

// 1. 按日期轮转的文件Handler（保留30天）
$rotatingHandler = new RotatingFileHandler(
    __DIR__ . '/logs/app.log',  // 文件路径
    30,                          // 保留天数
    Logger::DEBUG                // 最低记录级别
);
$rotatingHandler->setFormatter(new LineFormatter(
    "[%datetime%] %channel%.%level_name%: %message% %context% %extra%\n",
    'Y-m-d H:i:s.v'
));
$logger->pushHandler($rotatingHandler);

// 2. 错误级别单独写文件
$errorHandler = new StreamHandler(
    __DIR__ . '/logs/error.log',
    Logger::ERROR
);
$errorHandler->setFormatter(new JsonFormatter());
$logger->pushHandler($errorHandler);

// 使用
$logger->info('应用启动', ['version' => '2.1.0']);
$logger->warning('缓存未命中', ['key' => 'user_profile_123']);
$logger->error('支付失败', ['order_id' => 'ORD-20260531-001', 'error' => 'timeout']);
```

### Processor：自动注入上下文

```php
<?php
use Monolog\Processor\IntrospectionProcessor;
use Monolog\Processor\WebProcessor;
use Monolog\Processor\MemoryUsageProcessor;
use Monolog\Processor\ProcessIdProcessor;
use Monolog\Processor\UidProcessor;

// 1. 自动添加请求ID（用于链路追踪）
$logger->pushProcessor(new UidProcessor(8)); // 生成8位唯一ID

// 2. 自动记录调用位置（文件名、行号、方法名）
$logger->pushProcessor(new IntrospectionProcessor(
    Logger::WARNING, // 只在WARNING及以上级别记录
    ['Monolog\\', 'App\\Logger\\'] // 忽略这些命名空间的栈帧
));

// 3. Web请求信息（IP、URL、HTTP方法）
$logger->pushProcessor(new WebProcessor());

// 4. 内存使用量
$logger->pushProcessor(new MemoryUsageProcessor());

// 5. 自定义Processor：添加请求上下文
$logger->pushProcessor(function (array $record): array {
    $record['extra']['request_id'] = REQUEST_ID;
    $record['extra']['user_id'] = Auth::id() ?? 'guest';
    $record['extra']['trace_id'] = TraceContext::getTraceId();
    return $record;
});
```

### 多通道配置

```php
<?php
use Monolog\Handler\FingersCrossedHandler;
use Monolog\Handler\BufferHandler;
use Monolog\Handler\SlackWebhookHandler;
use Monolog\Handler\SyslogUdpHandler;

// 1. FingersCrossed：平时不记录，出错时回写之前的所有日志
//    适合调试生产环境偶发问题
$fingersCrossed = new FingersCrossedHandler(
    new StreamHandler(__DIR__ . '/logs/debug.log', Logger::DEBUG),
    Logger::WARNING,  // 触发级别：一旦出现WARNING，回写所有之前的DEBUG日志
    0,                 // 缓冲区大小：0=不限制
    true,              // 记录触发之后的消息
    true               // 缓冲区独立于级别
);
$logger->pushHandler($fingersCrossed);

// 2. Slack告警：CRITICAL级别发到Slack
$slackHandler = new SlackWebhookHandler(
    'https://hooks.slack.com/services/XXX/YYY/ZZZ',
    '#alerts',
    'ProductionBot',
    true,  // useAttachment
    null,
    false,
    Logger::CRITICAL
);
$logger->pushHandler($slackHandler);

// 3. 按业务通道分离
$logger->info('用户注册', ['channel' => 'user']); // 所有Handler都会收到
```

## 日志分级策略

### 生产环境最佳实践

```php
<?php
class LoggerFactory
{
    public static function create(string $name = 'app'): Logger
    {
        $logger = new Logger($name);
        $isProduction = getenv('APP_ENV') === 'production';

        if ($isProduction) {
            // 生产环境：INFO以上写入文件，ERROR以上发告警
            $logger->pushHandler(new RotatingFileHandler(
                __DIR__ . '/../logs/app.log', 30, Logger::INFO
            ));
            $logger->pushHandler(self::createAlertHandler());
        } else {
            // 开发环境：DEBUG以上写入文件，同时输出控制台
            $logger->pushHandler(new StreamHandler('php://stdout', Logger::DEBUG));
            $logger->pushHandler(new RotatingFileHandler(
                __DIR__ . '/../logs/debug.log', 7, Logger::DEBUG
            ));
        }

        // 公共Processor
        $logger->pushProcessor(new UidProcessor());
        $logger->pushProcessor(function (array $record): array {
            $record['extra']['memory'] = round(memory_get_usage(true) / 1024 / 1024, 2) . 'MB';
            return $record;
        });

        return $logger;
    }

    private static function createAlertHandler(): HandlerInterface
    {
        // 生产环境用FingersCrossed：正常请求不记录DEBUG日志，出错才回写
        return new FingersCrossedHandler(
            new RotatingFileHandler(__DIR__ . '/../logs/full-debug.log', 3, Logger::DEBUG),
            Logger::ERROR
        );
    }
}
```

### 日志格式规范

```php
<?php
// 推荐JSON格式（方便ELK/Grafana Loki等日志系统检索）
class CustomJsonFormatter extends JsonFormatter
{
    public function format(array $record): string
    {
        $record['datetime'] = $record['datetime']->format('Y-m-d\TH:i:s.vP');
        $record['app'] = getenv('APP_NAME');
        $record['env'] = getenv('APP_ENV');
        $record['host'] = gethostname();

        // 正常化context中的异常
        if (isset($record['context']['exception']) && $record['context']['exception'] instanceof Throwable) {
            $record['context']['exception'] = [
                'class' => get_class($record['context']['exception']),
                'message' => $record['context']['exception']->getMessage(),
                'file' => $record['context']['exception']->getFile(),
                'line' => $record['context']['exception']->getLine(),
            ];
        }

        return parent::format($record);
    }
}
```

## 面试常见追问

**Q: error_log()和Monolog有什么区别？什么时候用哪个？**
A: `error_log()`是PHP内置函数，简单直接但不支持分级、多通道、格式化。Monolog是工业级方案，支持Handler链、Processor、Formatter。小型脚本用`error_log()`足够，任何正式项目都应该用Monolog或实现PSR-3的日志库。

**Q: FingersCrossedHandler的原理是什么？性能影响大吗？**
A: 它内部维护一个ArrayHandler缓冲区，所有日志先写入缓冲区。当某条日志达到触发级别时，将缓冲区中所有日志一次性写入真实Handler。性能影响取决于缓冲区大小——如果正常请求不触发，缓冲区在请求结束时被丢弃，开销很小。适合"只在出错时才看详细日志"的场景。

**Q: 日志写入文件时怎么避免成为性能瓶颈？**
A: 三个策略：1) 用`BufferHandler`包装，批量写入减少IO；2) 异步写入（Swoole环境下用`Coroutine`+Channel）；3) 日志级别过滤——生产环境不要记录DEBUG级别。Monolog的Handler天然支持级别过滤，级别不匹配时直接返回false，零开销。
