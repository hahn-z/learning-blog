# PHP断言与调试技巧

## assert()断言机制

PHP的`assert()`用于在开发阶段验证假设，生产环境可以零开销关闭。

### PHP7/8的assert新语法

```php
<?php
// PHP7+: assert接受表达式（字符串形式已废弃）
assert($age > 0, '年龄必须大于0');

// PHP8.0+: assert接受Throwable作为失败时的异常
assert($user !== null, new AssertionError('用户不能为空'));

// 自定义断言回调
assert_options(ASSERT_CALLBACK, function (string $file, int $line, string $code, string $desc) {
    throw new AssertionError("断言失败: {$desc} in {$file}:{$line}");
});

// zend_assertions配置
// 1 = 生成并执行断言代码（开发环境）
// 0 = 生成但不执行（生产环境，代码存在但不运行）
// -1 = 不生成断言代码（生产环境，零开销）
// php.ini: zend.assertions = -1
```

### 断言的最佳实践

```php
<?php
// 1. 前置条件断言（输入验证）
function divide(float $a, float $b): float
{
    assert($b != 0, new AssertionError('除数不能为零'));
    return $a / $b;
}

// 2. 不变量断言（执行过程中应始终成立的条件）
function processOrder(Order $order): void
{
    $initialTotal = $order->getTotal();

    // ... 复杂的处理逻辑 ...

    assert(
        abs($order->getTotal() - $initialTotal) < 0.01,
        new AssertionError('处理前后总价不应变化')
    );
}

// 3. 后置条件断言（输出验证）
function getActiveUsers(PDO $pdo): array
{
    $users = $pdo->query("SELECT * FROM users WHERE active = 1")->fetchAll();
    assert(
        array_filter($users, fn($u) => !$u['active']) === [],
        new AssertionError('返回的用户应该都是活跃的')
    );
    return $users;
}
```

## Xdebug安装与配置

### 安装

```bash
# 方式1: pecl安装（推荐）
pecl install xdebug

# 方式2: Ubuntu/Debian
sudo apt install php8.3-xdebug

# 验证安装
php -m | grep xdebug
php -r "echo phpversion('xdebug');"
```

### php.ini配置

```ini
[xdebug]
zend_extension=xdebug.so

; 开启步骤调试（IDE断点调试）
xdebug.mode=debug
xdebug.start_with_request=yes

; 开启性能分析（可选）
; xdebug.mode=profile
; xdebug.output_dir=/tmp/xdebug-profile

; 开启覆盖率分析（测试用）
; xdebug.mode=coverage

; 开启追踪（函数调用追踪）
; xdebug.mode=trace
; xdebug.trace_format=1

; IDE连接配置
xdebug.client_host=127.0.0.1
xdebug.client_port=9003
xdebug.idekey=PHPSTORM

; 开发环境显示优化错误信息
xdebug.mode=debug,develop
xdebug.var_display_max_depth=5
xdebug.var_display_max_children=128
```

### Xdebug模式说明

Xdebug3将功能拆分为独立模式，通过`xdebug.mode`组合：

```
xdebug.mode=debug       → 步骤调试（断点、单步执行）
xdebug.mode=profile     → 性能分析（生成callgrind文件）
xdebug.mode=coverage    → 代码覆盖率
xdebug.mode=trace       → 函数调用追踪
xdebug.mode=develop     → 开发辅助（改进var_dump、错误堆栈）
xdebug.mode=debug,develop → 组合使用
```

## Kint调试工具

Kint是一个比`var_dump`可读性高得多的调试输出工具：

```php
<?php
require 'vendor/autoload.php';

// 基础用法
Kint\Renderer\RichRenderer::$folder = false; // 默认折叠
$d = Kint\dump($variable);
// 或者用全局函数
d($variable);          // 调试输出
dd($variable);         // 调试输出并die
s($variable);          // 简洁文本模式
~d($variable);         // 追踪模式（显示调用栈）

// 特定深度限制
Kint::$max_depth = 3;
d($deepObject);

// 自定义显示
Kint::$aliases[] = 'my_debug';
function my_debug(...$args) {
    return Kint\dump(...$args);
}
```

## Symfony VarDumper

Laravel的`dump()`和`dd()`底层就是VarDumper：

```php
<?php
require 'vendor/autoload.php';

use Symfony\Component\VarDumper\VarDumper;
use Symfony\Component\VarDumper\Dumper\ContextualizedDumper;
use Symfony\Component\VarDumper\Caster\ReflectionCaster;

// 基础用法
dump($variable);           // 输出并继续
dd($variable);             // 输出并终止

// 多变量
dump($user, $orders, $config);

// dump到文件或自定义目标
$cloner = new Symfony\Component\VarDumper\Cloner\VarCloner();
$cloner->addCasters(ReflectionCaster::UNSET_CLOSURE_FILE_INFO);
$dumper = new Symfony\Component\VarDumper\Dumper\CliDumper();
$dumper->dump($cloner->cloneVar($data));
```

## 自定义dd()实现

```php
<?php
/**
 * 增强版dd() - 带调用位置和时序信息
 */
function dd(...$vars): never
{
    $trace = debug_backtrace(DEBUG_BACKTRACE_IGNORE_ARGS, 1)[0];

    // CLI环境用纯文本
    if (php_sapi_name() === 'cli') {
        foreach ($vars as $i => $var) {
            echo "┌─ Dump #{$i} ───────────────────\n";
            echo "│ File: {$trace['file']}:{$trace['line']}\n";
            echo "├────────────────────────────\n";
            print_r($var);
            echo "\n";
        }
        exit(1);
    }

    // Web环境输出HTML
    http_response_code(500);
    header('Content-Type: text/html; charset=utf-8');
    echo '<pre style="background:#1e1e1e;color:#d4d4d4;padding:20px;border-radius:8px;font-size:14px;overflow:auto;">';
    echo "📍 {$trace['file']}:{$trace['line']}\n\n";
    foreach ($vars as $i => $var) {
        echo "── Dump #{$i} ──\n";
        var_export($var);
        echo "\n\n";
    }
    echo '</pre>';
    exit(1);
}

/**
 * 调试日志版 - 不打断执行
 */
function dlog(...$vars): void
{
    $trace = debug_backtrace(DEBUG_BACKTRACE_IGNORE_ARGS, 1)[0];
    foreach ($vars as $var) {
        error_log(sprintf(
            "[DLOG] %s:%d %s",
            $trace['file'],
            $trace['line'],
            is_string($var) ? $var : json_encode($var, JSON_UNESCAPED_UNICODE)
        ));
    }
}
```

## 面试常见追问

**Q: assert和if+throw有什么区别？**
A: `assert`表达的是"我认为这个条件一定成立"，是开发者对程序逻辑的验证。`if+throw`是防御性编程。关键区别：生产环境中`zend.assertions=-1`时，assert代码完全不执行（零开销），而if始终执行。所以assert适合开发阶段的契约验证，不适合运行时校验。

**Q: Xdebug对性能影响有多大？生产环境能用吗？**
A: Xdebug的debug模式会导致所有请求变慢2-10倍，因为它需要在每个PHP语句后检查断点。profile模式只在请求结束时写入文件，运行时开销较小。**生产环境绝对不要开启Xdebug的debug模式**。如果需要生产调试，考虑使用Blackfire或Tideways等专门的生产级性能分析工具。

**Q: dd()和var_dump+exit的区别？**
A: `dd()`（无论是Laravel的还是自定义的）通常有更好的格式化输出、显示调用位置、区分CLI/Web环境。`var_dump`+`exit`是原始方案。在生产代码中两者都不应该出现——它们是开发调试工具。
