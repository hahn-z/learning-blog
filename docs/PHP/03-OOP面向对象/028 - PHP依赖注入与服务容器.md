# PHP依赖注入与服务容器

依赖注入（DI）和控制反转（IoC）是现代 PHP 框架的核心设计理念。理解 DI 的三种方式、IoC 容器的原理、以及 Laravel Container 的实现思路，是进阶 PHP 开发者的必修课。

## 为什么需要依赖注入

```php
<?php
// ❌ 硬编码依赖 — 紧耦合
class UserController
{
    public function list(): array
    {
        $db = new MySQLDatabase('localhost', 'root', ''); // 直接依赖具体实现
        $cache = new RedisCache('127.0.0.1');              // 无法替换
        return $db->query('SELECT * FROM users');
    }
}

// ✅ 依赖注入 — 松耦合
class UserController
{
    public function __construct(
        private DatabaseInterface $db,
        private CacheInterface $cache,
    ) {}

    public function list(): array
    {
        $cached = $this->cache->get('users');
        if ($cached) return $cached;

        $users = $this->db->query('SELECT * FROM users');
        $this->cache->set('users', $users, 3600);
        return $users;
    }
}
```

**依赖注入的好处：** (1) 解耦——依赖抽象而非具体实现；(2) 可测试——可以注入 Mock 对象；(3) 可配置——运行时替换实现。

## DI 的三种方式

### 1. 构造函数注入（推荐）

```php
<?php
class OrderService
{
    // 必需依赖通过构造函数注入
    public function __construct(
        private PaymentGateway $payment,
        private OrderRepository $orders,
        private NotificationInterface $notification,
    ) {}

    public function placeOrder(Order $order): OrderResult
    {
        $result = $this->payment->charge($order->getTotal());
        $this->orders->save($order);
        $this->notification->send("Order #{$order->getId()} placed");
        return $result;
    }
}
```

### 2. Setter 注入

```php
<?php
class MailService
{
    private ?LoggerInterface $logger = null;

    // 可选依赖通过 setter 注入
    public function setLogger(LoggerInterface $logger): void
    {
        $this->logger = $logger;
    }

    public function send(string $to, string $body): void
    {
        $this->logger?->log("Sending email to $to");
        // ...
    }
}
```

### 3. 接口注入

```php
<?php
interface LoggerAwareInterface
{
    public function setLogger(LoggerInterface $logger): void;
}

class ReportGenerator implements LoggerAwareInterface
{
    private ?LoggerInterface $logger = null;

    public function setLogger(LoggerInterface $logger): void
    {
        $this->logger = $logger;
    }
}
```

**三种方式对比：**

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| 构造函数 | 必需依赖 | 强制提供、不可变 | 参数多时构造函数膨胀 |
| Setter | 可选依赖 | 灵活、可后期修改 | 依赖可能为 null |
| 接口注入 | 框架标准化 | 统一契约 | 侵入性强、复杂 |

## IoC 容器原理

IoC 容器自动管理依赖关系，无需手动创建和注入对象：

```php
<?php
class Container
{
    private array $bindings = [];   // 抽象 → 具体绑定
    private array $instances = [];  // 单例实例
    private array $resolving = [];  // 正在解析的（防止循环依赖）

    // 绑定接口到实现
    public function bind(string $abstract, callable|string|null $concrete = null): void
    {
        $this->bindings[$abstract] = [
            'concrete' => $concrete ?? $abstract,
            'singleton' => false,
        ];
    }

    // 绑定单例
    public function singleton(string $abstract, callable|string|null $concrete = null): void
    {
        $this->bindings[$abstract] = [
            'concrete' => $concrete ?? $abstract,
            'singleton' => true,
        ];
    }

    // 解析实例
    public function make(string $abstract): object
    {
        // 已有单例实例
        if (isset($this->instances[$abstract])) {
            return $this->instances[$abstract];
        }

        $concrete = $this->getConcrete($abstract);
        $object = $this->build($concrete);

        // 如果是单例，缓存实例
        if (isset($this->bindings[$abstract]) && $this->bindings[$abstract]['singleton']) {
            $this->instances[$abstract] = $object;
        }

        return $object;
    }

    private function getConcrete(string $abstract): string
    {
        return isset($this->bindings[$abstract])
            ? $this->bindings[$abstract]['concrete']
            : $abstract;
    }

    // 自动解析：通过反射读取构造函数依赖
    private function build(string $concrete): object
    {
        $reflector = new ReflectionClass($concrete);

        if (!$reflector->isInstantiable()) {
            throw new RuntimeException("Class $concrete is not instantiable");
        }

        $constructor = $reflector->getConstructor();

        if ($constructor === null) {
            return new $concrete();
        }

        // 解析构造函数参数
        $parameters = $constructor->getParameters();
        $dependencies = $this->resolveDependencies($parameters);

        return $reflector->newInstanceArgs($dependencies);
    }

    private function resolveDependencies(array $parameters): array
    {
        $dependencies = [];

        foreach ($parameters as $parameter) {
            $type = $parameter->getType();

            if ($type instanceof ReflectionNamedType && !$type->isBuiltin()) {
                // 类类型参数 — 递归解析
                $dependencies[] = $this->make($type->getName());
            } elseif ($parameter->isDefaultValueAvailable()) {
                // 有默认值 — 使用默认值
                $dependencies[] = $parameter->getDefaultValue();
            } else {
                throw new RuntimeException(
                    "Cannot resolve parameter \${$parameter->getName()} in {$parameter->getDeclaringClass()?->getName()}"
                );
            }
        }

        return $dependencies;
    }
}
```

## 使用容器

```php
<?php
// 定义接口
interface DatabaseInterface
{
    public function query(string $sql): array;
}

class MySQLDatabase implements DatabaseInterface
{
    public function query(string $sql): array { /* ... */ return []; }
}

interface CacheInterface
{
    public function get(string $key): mixed;
    public function set(string $key, mixed $value, int $ttl = 0): void;
}

class RedisCache implements CacheInterface
{
    public function get(string $key): mixed { return null; }
    public function set(string $key, mixed $value, int $ttl = 0): void {}
}

// 注册绑定
$container = new Container();
$container->bind(DatabaseInterface::class, MySQLDatabase::class);
$container->singleton(CacheInterface::class, RedisCache::class);

// 自动解析 UserController 的所有依赖
$controller = $container->make(UserController::class);
// Container 自动：
// 1. 发现 UserController 需要 DatabaseInterface 和 CacheInterface
// 2. 解析绑定的具体类
// 3. 递归解析具体类的依赖
// 4. 创建并注入所有依赖
```

## Laravel Container 核心思路

Laravel 的 Container 是 PHP 生态最强大的 IoC 容器，核心功能包括：

```php
<?php
// Laravel 风格的绑定
$app = new Illuminate\Container\Container();

// 1. 简单绑定
$app->bind(PaymentGatewayInterface::class, StripeGateway::class);

// 2. 闭包绑定（自定义创建逻辑）
$app->bind(DatabaseInterface::class, function($app) {
    return new MySQLDatabase(
        host: config('db.host'),
        user: config('db.user'),
    );
});

// 3. 单例绑定
$app->singleton(CacheInterface::class, RedisCache::class);

// 4. 实例绑定
$app->instance(Config::class, new Config(['debug' => true]));

// 5. 上下文绑定（不同类注入不同实现）
$app->when(OrderController::class)
    ->needs(PaymentGatewayInterface::class)
    ->give(StripeGateway::class);

$app->when(SubscriptionController::class)
    ->needs(PaymentGatewayInterface::class)
    ->give(PaypalGateway::class);

// 6. 标签绑定
$app->tag([RedisCache::class, FileCache::class], 'cache-drivers');
$app->tagged('cache-drivers'); // 获取所有标记的实现

// 7. 自动注入零配置（无需 bind）
// 如果类没有接口依赖，Container 直接反射创建
$controller = $app->make(UserController::class);
```

**Laravel Container 的关键源码机制：**
1. **`build()` 方法**：通过 `ReflectionClass` 分析构造函数，递归解析依赖
2. **`resolveDependencies()`**：遍历 `ReflectionParameter`，按类型提示自动注入
3. **`getConcrete()`**：查找绑定 → 上下文绑定 → 自动解析
4. **`rebound()`**：重新绑定时触发回调（用于 `config:cache` 等热更新场景）
5. **循环依赖检测**：通过 `$buildStack` 追踪，检测到循环抛出异常

## 面试常见追问

**Q: DI 和 Service Locator 的区别？**

A: DI 是被动接收依赖（通过构造函数/setter），Service Locator 是主动拉取依赖（`$container->get('db')`）。DI 更符合 IoC 原则（控制反转），Service Locator 本质是"控制正转"（类自己知道容器的存在）。Laravel 的 Facade 本质是 Service Locator。

**Q: IoC 容器如何处理循环依赖？**

A: 在解析过程中维护一个栈（`$buildStack`），如果发现正在解析的类已经在栈中，说明存在循环依赖，抛出异常。解决方案：(1) 重构设计消除循环；(2) 用 Setter 注入打破循环（先创建对象再注入）。

**Q: PHP 的反射性能如何？容器有没有性能问题？**

A: 反射确实比直接 `new` 慢（约 2-5 倍），但在请求生命周期中只发生一次。生产环境优化：(1) Laravel 的 `php artisan optimize` 将容器绑定编译为原生 PHP 代码；(2) Symfony 用 `jc/cli` 生成容器的 PHP 文件，无反射开销。

**Q: 什么时候不应该用 DI 容器？**

A: 小型项目/脚本中手动注入更简单。容器适合中大型项目——依赖关系复杂、需要统一管理生命周期。过度使用容器会导致代码不直观（"魔法"太多）。

## 小结

依赖注入是"依赖抽象，不依赖具体"的实践手段。三种注入方式中构造函数注入最常用、最安全。IoC 容器通过反射实现自动解析，Laravel Container 是 PHP 生态最成熟的实现。理解容器原理后，框架中各种"自动注入"就不再神秘了。
