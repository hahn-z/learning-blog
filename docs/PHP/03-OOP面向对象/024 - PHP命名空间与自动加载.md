---# PHP命名空间与自动加载

命名空间解决类名冲突，自动加载消除手动 `require`。两者结合，加上 PSR-4 规范，构成了现代 PHP 工程化的基础设施。

## 命名空间基础

```php
<?php
// 声明命名空间（必须是文件第一条语句）
namespace App\Services;

class Mailer
{
    public function send(string $to, string $body): void
    {
        echo "Sending to $to: $body\n";
    }
}

// 完全限定名引用
$mailer = new \App\Services\Mailer();

// 同命名空间内直接使用
$mailer2 = new Mailer();
```

### 子命名空间

```php
<?php
namespace App\Services\Email;

class SmtpMailer
{
    public function send(string $to, string $body): void { /* ... */ }
}
```

**命名空间映射到目录结构：** `App\Services\Email\SmtpMailer` → `src/Services/Email/SmtpMailer.php`

## use 导入与别名

```php
<?php
namespace App\Controllers;

// 基础导入
use App\Services\Mailer;
use App\Services\Email\SmtpMailer;

// 别名
use App\Services\Email\SmtpMailer as EmailService;

// 函数导入（PHP 5.6+）
use function App\Utils\helpers\slugify;

// 常量导入
use const App\Config\MAX_RETRIES;

// 组合导入（PHP 7+）
use App\Services\{Mailer, Email\SmtpMailer};
use App\Repositories\{UserRepository, PostRepository as PostRepo};

class UserController
{
    public function register(): void
    {
        $mailer = new Mailer();         // 不用写全名
        $email  = new EmailService();   // 使用别名
    }
}
```

**全局命名空间的注意点：** 命名空间内调用内置函数/类时，PHP 先在当前命名空间查找，找不到再回退到全局。但 `new Exception()` 在 `App\Services` 中会先找 `App\Services\Exception`。建议用 `\Exception()` 明确指定全局类。

## 自动加载：从 __autoload 到 spl_autoload_register

```php
<?php
// PHP 5 的 __autoload（已废弃）— 只能注册一个自动加载器
function __autoload(string $class) {
    require str_replace('\\', '/', $class) . '.php';
}

// PHP 5.1+ 的 spl_autoload_register — 推荐方式
spl_autoload_register(function(string $class) {
    $file = str_replace('\\', '/', $class) . '.php';
    if (file_exists($file)) {
        require $file;
    }
});

// 可以注册多个加载器，按注册顺序执行
spl_autoload_register(function(string $class) {
    // 从 vendor 目录查找
    $file = 'vendor/' . str_replace('\\', '/', $class) . '.php';
    if (file_exists($file)) {
        require $file;
    }
});
```

## PSR-4 规范

PSR-4 是 PHP-FIG 制定的自动加载标准，定义了命名空间到文件路径的映射规则：

> 完整的类名 = 命名空间前缀 + 子命名空间 + 类名 → 文件路径 = 基目录 + 子目录 + 类名.php

```
命名空间前缀: App\
基目录:       src/

App\Controller\UserController → src/Controller/UserController.php
App\Model\Entity\Order        → src/Model/Entity/Order.php
App\Kernel                    → src/Kernel.php
```

### 手动实现 PSR-4 自动加载器

```php
<?php
class Psr4Autoloader
{
    private array $prefixes = [];

    // 注册命名空间前缀到基目录的映射
    public function addNamespace(string $prefix, string $baseDir): void
    {
        $prefix = trim($prefix, '\\') . '\\';
        $baseDir = rtrim($baseDir, '/') . '/';
        $this->prefixes[$prefix] = $baseDir;
    }

    public function register(): void
    {
        spl_autoload_register([$this, 'loadClass']);
    }

    public function loadClass(string $class): void
    {
        foreach ($this->prefixes as $prefix => $baseDir) {
            if (str_starts_with($class, $prefix)) {
                $relativeClass = substr($class, strlen($prefix));
                $file = $baseDir . str_replace('\\', '/', $relativeClass) . '.php';
                if (file_exists($file)) {
                    require $file;
                    return;
                }
            }
        }
    }
}

$loader = new Psr4Autoloader();
$loader->addNamespace('App\\', 'src/');
$loader->addNamespace('Framework\\', 'framework/');
$loader->register();
```

## Composer autoload

Composer 内置了 PSR-4 自动加载支持，是实际项目中的标准方案：

```json
{
    "autoload": {
        "psr-4": {
            "App\\": "src/",
            "Framework\\": "framework/"
        },
        "files": ["src/helpers.php"],
        "classmap": ["database/seeds/"]
    },
    "autoload-dev": {
        "psr-4": {
            "Tests\\": "tests/"
        }
    }
}
```

```bash
# 生成/更新自动加载文件
composer dump-autoload
composer dump-autoload -o  # 优化：生成类映射文件（生产环境）
```

**Composer autoload 的三种方式：**
1. **`psr-4`** — 按命名空间映射（推荐，开发环境）
2. **`classmap`** — 扫描目录生成类映射（生产优化）
3. **`files`** — 每次请求都加载的文件（全局函数/常量）

### autoload 优化原理

`composer dump-autoload -o` 会扫描所有类文件，生成一个完整的 `类名 → 文件路径` 映射表（`vendor/composer/autoload_classmap.php`）。加载类时直接查表，无需文件系统遍历，显著提升性能。

## 面试常见追问

**Q: PSR-4 和 PSR-0 的区别？**

A: PSR-0 要求类名中的下划线 `_` 映射为目录分隔符（`Zend_Db_Adapter` → `Zend/Db/Adapter.php`），且命名空间必须从顶层开始。PSR-4 取消了下划线规则，支持命名空间前缀映射（`App\` → `src/`），目录结构更灵活。PSR-0 已废弃。

**Q: 命名空间和目录结构必须一致吗？**

A: 不强制，但 PSR-4 规范要求一致才能实现自动加载。非 PSR-4 项目可以用 `classmap` 扫描，但推荐遵循规范。

**Q: `require` 和 `include` 的区别？**

A: `require` 找不到文件触发 Fatal Error（脚本终止），`include` 触发 Warning（继续执行）。自动加载中用 `require`（类文件缺失应终止）。`require_once`/`include_once` 有额外的去重检查开销，自动加载已保证不重复加载，无需 `_once`。

**Q: 同一个类在多个自动加载器中都存在会怎样？**

A: 先找到的那个生效。`spl_autoload_register` 按注册顺序依次调用加载器，第一个成功加载的胜出。这也是 Composer 加载器优先级机制的基础。

## 小结

命名空间解决命名冲突，PSR-4 定义命名空间到文件路径的映射规则，Composer 自动生成自动加载文件。实际开发中只需配置 `composer.json` 的 `autoload.psr-4`，然后 `composer dump-autoload`。
