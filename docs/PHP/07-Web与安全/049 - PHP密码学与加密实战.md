# PHP密码学与加密实战

密码学在Web开发中无处不在：用户密码存储、数据传输加密、JWT令牌签发。用对API很容易，用错后果很严重。

## 密码哈希：password_hash家族

### 为什么不能用MD5/SHA256存密码

MD5和SHA是**快速哈希**，设计目的是校验数据完整性。GPU每秒可以计算数十亿次MD5，暴力破解成本极低。密码哈希需要的是**慢哈希**——故意增加计算成本。

### password_hash正确用法

```php
<?php
// 使用Bcrypt（默认，成熟稳定）
$hash = password_hash('myPassword123', PASSWORD_BCRYPT, ['cost' => 12]);
// 输出: $2y$12$xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
// 格式: $算法$cost$22字符salt+31字符hash

// 使用Argon2id（PHP 7.3+，更现代）
$hash = password_hash('myPassword123', PASSWORD_ARGON2ID, [
    'memory_cost' => 65536,  // 64MB内存消耗
    'time_cost'   => 4,      // 4轮迭代
    'threads'     => 2,      // 2线程并行
]);

// 验证密码（时间恒定比较，防时序攻击）
if (password_verify($userInput, $storedHash)) {
    // 检查是否需要重新哈希（算法升级、cost调整）
    if (password_needs_rehash($storedHash, PASSWORD_BCRYPT, ['cost' => 13])) {
        $newHash = password_hash($userInput, PASSWORD_BCRYPT, ['cost' => 13]);
        // 更新数据库中的hash
    }
    echo '密码正确';
}
```

### cost参数怎么选

cost每增加1，计算时间翻倍。Bcrypt的cost=10约100ms，cost=12约400ms。**原则：用户登录可接受的延迟内，尽量提高cost**。

```php
<?php
// 自动测试合适的cost值（目标约250ms）
function findOptimalCost(): int {
    $targetTime = 0.25; // 250ms
    for ($cost = 10; $cost <= 20; $cost++) {
        $start = microtime(true);
        password_hash('test', PASSWORD_BCRYPT, ['cost' => $cost]);
        $elapsed = microtime(true) - $start;
        if ($elapsed >= $targetTime) {
            return $cost;
        }
    }
    return 15;
}
```

## 对称加密：openssl_encrypt

当需要**可逆加密**（如加密存储API Key、敏感配置）时使用：

```php
<?php
class AES256Encryptor {
    private string $cipher = 'aes-256-gcm';  // GCM模式提供认证加密
    
    public function encrypt(string $plaintext, string $key): string {
        $iv = random_bytes(12);  // GCM推荐12字节IV
        $tag = '';               // 认证标签
        
        $ciphertext = openssl_encrypt(
            $plaintext,
            $this->cipher,
            $key,              // 必须是256位(32字节)
            OPENSSL_RAW_DATA,
            $iv,
            $tag,
            '',                // AAD（附加认证数据，可选）
            16                 // tag长度
        );
        
        // 返回 iv + tag + ciphertext（base64编码方便存储）
        return base64_encode($iv . $tag . $ciphertext);
    }
    
    public function decrypt(string $encoded, string $key): ?string {
        $data = base64_decode($encoded);
        $iv = substr($data, 0, 12);
        $tag = substr($data, 12, 16);
        $ciphertext = substr($data, 28);
        
        $result = openssl_decrypt(
            $ciphertext,
            $this->cipher,
            $key,
            OPENSSL_RAW_DATA,
            $iv,
            $tag
        );
        
        return $result !== false ? $result : null;
    }
}

// 使用示例
$key = hash('sha256', 'your-secret-key-from-env', true); // 确保32字节
$encryptor = new AES256Encryptor();
$encrypted = $encryptor->encrypt('sk-api-xxxx-yyyy', $key);
$decrypted = $encryptor->decrypt($encrypted, $key);
```

**为什么用GCM而不是CBC？** CBC模式需要手动处理padding和HMAC认证，容易出错（如Mac-then-Encrypt vs Encrypt-then-Mac）。GCM是认证加密，同时保证机密性和完整性。

## JWT手动实现

理解JWT原理比用库更重要。JWT由三部分组成：Header.Payload.Signature。

```php
<?php
class SimpleJWT {
    private string $secret;
    
    public function __construct(string $secret) {
        $this->secret = $secret;
    }
    
    public function encode(array $payload, int $expireSeconds = 3600): string {
        $header = ['typ' => 'JWT', 'alg' => 'HS256'];
        
        $payload['iat'] = time();                           // 签发时间
        $payload['exp'] = time() + $expireSeconds;          // 过期时间
        $payload['jti'] = bin2hex(random_bytes(8));          // 唯一ID防重放
        
        $headerEncoded = $this->base64UrlEncode(json_encode($header));
        $payloadEncoded = $this->base64UrlEncode(json_encode($payload));
        
        $signature = hash_hmac(
            'sha256',
            "$headerEncoded.$payloadEncoded",
            $this->secret,
            true
        );
        $signatureEncoded = $this->base64UrlEncode($signature);
        
        return "$headerEncoded.$payloadEncoded.$signatureEncoded";
    }
    
    public function decode(string $token): ?array {
        $parts = explode('.', $token);
        if (count($parts) !== 3) return null;
        
        [$headerEncoded, $payloadEncoded, $signatureEncoded] = $parts;
        
        // 验证签名
        $expectedSig = $this->base64UrlEncode(hash_hmac(
            'sha256',
            "$headerEncoded.$payloadEncoded",
            $this->secret,
            true
        ));
        
        if (!hash_equals($expectedSig, $signatureEncoded)) {
            return null; // 签名无效
        }
        
        $payload = json_decode($this->base64UrlDecode($payloadEncoded), true);
        
        // 验证过期
        if (isset($payload['exp']) && $payload['exp'] < time()) {
            return null; // 已过期
        }
        
        return $payload;
    }
    
    private function base64UrlEncode(string $data): string {
        return rtrim(strtr(base64_encode($data), '+/', '-_'), '=');
    }
    
    private function base64UrlDecode(string $data): string {
        return base64_decode(strtr($data, '-_', '+/'));
    }
}

// 使用
$jwt = new SimpleJWT('your-256-bit-secret-key-here!!');
$token = $jwt->encode(['user_id' => 42, 'role' => 'admin']);
$decoded = $jwt->decode($token);
```

## 面试常见追问

**Q: Bcrypt和Argon2怎么选？**
A: Bcrypt成熟广泛支持，但只消耗CPU。Argon2同时消耗内存和CPU，抗GPU/ASIC攻击更强。新项目推荐Argon2id，兼容性考虑用Bcrypt（cost≥12）。

**Q: AES-256-CBC和AES-256-GCM有什么区别？**
A: CBC只加密不认证，需要额外HMAC。GCM同时加密和认证，一步到位。实际中GCM更安全，因为CBC常因认证实现不当出问题（如Padding Oracle攻击）。

**Q: JWT的secret应该多长？**
A: HS256要求至少256位（32字节）。用`random_bytes(32)`生成，不要用人类可读的短密码。生产环境建议RS256（非对称），私钥签名公钥验证。

**Q: JWT可以被撤销吗？**
A: 原生JWT无法撤销（无状态设计）。方案：1) 短过期+Refresh Token；2) 黑名单（Redis存已注销的jti）；3) 每次敏感操作后轮换Token。

**Q: 为什么password_hash不需要手动加盐？**
A: `password_hash`自动生成随机盐并嵌入哈希结果中。手动加盐反而容易出错（盐太短、盐固定、盐和密码拼接方式不安全）。
