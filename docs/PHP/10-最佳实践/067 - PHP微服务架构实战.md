# PHP微服务架构实战

微服务不是银弹，但对复杂业务确实有效。本文从PHP视角出发，覆盖服务拆分、通信、治理和容器化的实战知识。

## 服务拆分原则

### 拆分依据

```
单体应用
├── 用户服务 (User Service)       ← 用户注册、认证、权限
├── 订单服务 (Order Service)      ← 下单、支付、物流
├── 商品服务 (Product Service)    ← 商品CRUD、库存
├── 通知服务 (Notification Service) ← 邮件、短信、推送
└── 报表服务 (Report Service)     ← 数据统计、导出
```

**拆分标准**：
1. **业务边界清晰**：按限界上下文拆（DDD概念）
2. **独立部署**：改动频繁的独立拆出来
3. **数据独立**：每个服务有自己的数据库
4. **团队归属**：不同团队负责不同服务

### 拆分前后对比

```php
<?php
// 拆分前：单体中直接调用
class OrderController {
    public function create(Request $request) {
        $user = User::find($request->user_id);          // 本地DB
        $product = Product::find($request->product_id);  // 本地DB
        $stock = Stock::decrease($product->id, 1);       // 本地DB
        
        $order = Order::create([...]);
        Mail::send(new OrderCreated($order));             // 本地调用
        
        return $order;
    }
}

// 拆分后：通过HTTP/gRPC调用
class OrderController {
    public function __construct(
        private UserServiceClient $userClient,
        private ProductServiceClient $productClient,
        private NotificationServiceClient $notifyClient,
    ) {}

    public function create(Request $request): Response {
        // 远程调用各服务
        $user = $this->userClient->getProfile($request->user_id);
        $product = $this->productClient->getDetail($request->product_id);
        $this->productClient->decreaseStock($request->product_id, 1);
        
        $order = $this->orderRepository->create([...]);
        
        // 异步通知
        $this->notifyClient->sendOrderCreated($order->id);
        
        return response()->json($order, 201);
    }
}
```

## gRPC vs HTTP通信

### HTTP REST（简单直接）

```php
<?php
class ServiceClient
{
    public function __construct(
        private readonly string $baseUrl,
        private readonly int $timeout = 5,
    ) {}

    public function get(string $path, array $query = []): array
    {
        $url = $this->baseUrl . $path . ($query ? '?' . http_build_query($query) : '');
        
        $ch = curl_init($url);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT => $this->timeout,
            CURLOPT_HTTPHEADER => [
                'Content-Type: application/json',
                'X-Service-Auth: ' . $this->getServiceToken(),
                'X-Request-ID: ' . $this->generateRequestId(),
            ],
        ]);
        
        $response = curl_exec($ch);
        $httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        curl_close($ch);
        
        if ($httpCode >= 400) {
            throw new ServiceException("Service call failed: HTTP $httpCode");
        }
        
        return json_decode($response, true);
    }

    public function post(string $path, array $data): array { /* 类似 */ }

    private function getServiceToken(): string
    {
        // 服务间认证Token（JWT）
        return $this->token ??= $this->generateServiceToken();
    }
}
```

### gRPC（高性能、强类型）

```protobuf
// proto/user.proto
syntax = "proto3";

package user;

service UserService {
    rpc GetProfile (GetProfileRequest) returns (UserResponse);
    rpc ValidateToken (ValidateTokenRequest) returns (ValidateTokenResponse);
}

message GetProfileRequest {
    int32 user_id = 1;
}

message UserResponse {
    int32 id = 1;
    string name = 2;
    string email = 3;
    string role = 4;
}

message ValidateTokenRequest {
    string token = 1;
}

message ValidateTokenResponse {
    bool valid = 1;
    int32 user_id = 2;
}
```

```bash
# 生成PHP代码
grpc_tools_php_protoc \
    --php_out=generated \
    --grpc_out=generated \
    proto/user.proto
```

```php
<?php
// gRPC客户端
class UserGrpcClient
{
    private \User\UserServiceClient $client;

    public function __construct(string $host)
    {
        $this->client = new \User\UserServiceClient($host, [
            'credentials' => Grpc\ChannelCredentials::createInsecure(),
        ]);
    }

    public function getProfile(int $userId): array
    {
        $request = new \User\GetProfileRequest();
        $request->setUserId($userId);

        [$response, $status] = $this->client->GetProfile($request)->wait();

        if ($status->code !== Grpc\STATUS_OK) {
            throw new ServiceException("gRPC error: {$status->details}");
        }

        return [
            'id' => $response->getId(),
            'name' => $response->getName(),
            'email' => $response->getEmail(),
        ];
    }
}
```

| 特性 | HTTP REST | gRPC |
|------|-----------|------|
| 协议 | HTTP/1.1 | HTTP/2 |
| 序列化 | JSON（文本） | Protobuf（二进制） |
| 类型安全 | 无 | 强类型 |
| 性能 | 一般 | 高（3-10倍） |
| 调试 | 容易（curl即可） | 需要工具 |
| 浏览器支持 | 原生 | 需要gRPC-Web |
| PHP生态 | 成熟 | 需要扩展 |

**建议**：服务间高频调用用gRPC，对外API用REST。

## 配置中心

```php
<?php
// Nacos配置中心客户端
class NacosConfigClient
{
    public function __construct(
        private string $serverAddr,
        private string $namespace,
    ) {}

    public function getConfig(string $dataId, string $group = 'DEFAULT'): array
    {
        $url = sprintf('%s/nacos/v1/cs/configs?dataId=%s&group=%s&tenant=%s',
            $this->serverAddr, $dataId, $group, $this->namespace);

        $response = file_get_contents($url);
        return json_decode($response, true);
    }

    // 长轮询监听配置变更
    public function listen(string $dataId, callable $onChange): void
    {
        while (true) {
            $ch = curl_init("{$this->serverAddr}/nacos/v1/cs/configs/listener");
            curl_setopt_array($ch, [
                CURLOPT_POST => true,
                CURLOPT_POSTFIELDS => http_build_query([
                    'Listening-Configs' => "{$dataId}\x02{$group}\x01\n",
                    'tenant' => $this->namespace,
                ]),
                CURLOPT_TIMEOUT => 30, // 长轮询30秒
                CURLOPT_RETURNTRANSFER => true,
            ]);

            $result = curl_exec($ch);
            if (!empty(trim($result))) {
                $config = $this->getConfig($dataId, $group);
                $onChange($config);
            }
        }
    }
}
```

## 链路追踪

```php
<?php
// Jaeger追踪集成
class TracingMiddleware
{
    private OpenTracing\Tracer $tracer;

    public function __construct()
    {
        $config = new \Jaeger\Config([
            'sampler' => ['type' => 'const', 'param' => 1],
            'local_agent' => ['reporting_host' => 'jaeger-agent'],
        ], 'order-service');
        $this->tracer = $config->initializeTracer();
    }

    public function handle(Request $request, callable $next): Response
    {
        // 从请求头提取追踪上下文
        $context = $this->extractContext($request);
        
        $span = $this->tracer->startSpan(
            $request->method() . ' ' . $request->path(),
            ['child_of' => $context]
        );

        try {
            $response = $next($request);
            $span->setTag('http.status_code', $response->getStatusCode());
            return $response;
        } catch (\Throwable $e) {
            $span->setTag('error', true);
            $span->log(['error.message' => $e->getMessage()]);
            throw $e;
        } finally {
            $span->finish();
            $this->tracer->flush();
        }
    }

    // 服务间调用时注入追踪头
    public function injectHeaders(array &$headers): void
    {
        $span = $this->tracer->getActiveSpan();
        if ($span) {
            $headers['uber-trace-id'] = $this->formatTraceContext($span);
        }
    }
}
```

## 面试常见追问

**Q: PHP适合做微服务吗？**
A: 适合，但不是最优。PHP的请求-响应模型天然无状态，适合水平扩展。缺点是常驻进程支持不如Go/Java（但Swoole/RoadRunner可以弥补）。中小规模微服务用PHP完全没问题。

**Q: 服务间数据库共享可以吗？**
A: 不可以，这是微服务的基本原则。共享数据库导致耦合：表结构变更影响多个服务，无法独立部署。正确做法是每个服务有自己的数据库，需要数据通过API交互。

**Q: 如何处理分布式事务？**
A: 1) Saga模式：编排一系列本地事务，每步失败执行补偿操作；2) 最终一致性：事件驱动，不追求实时一致；3) 避免跨服务事务（重新审视服务边界）。

**Q: 微服务和单体怎么选？**
A: 一人团队/小项目用单体（运维成本低）。团队>5人、业务模块>5个、部署频率高时考虑微服务。可以先模块化单体，需要时再拆。不要为了微服务而微服务。
