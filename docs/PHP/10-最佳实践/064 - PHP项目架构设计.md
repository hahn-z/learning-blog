---# PHP项目架构设计

架构设计决定了代码的可维护性和扩展性。本文从经典的分层架构讲起，到充血模型和六边形架构，帮助你做出合理的架构选择。

## 分层架构：Controller-Service-Repository

最常见的PHP项目架构，简单实用：

```
Controller → 接收请求，参数验证，返回响应
    ↓
Service → 业务逻辑编排
    ↓
Repository → 数据访问
    ↓
Model/Entity → 数据结构
```

### 目录结构

```
app/
├── Http/Controllers/       # 控制器层
│   ├── Api/
│   │   └── UserController.php
│   └── Web/
├── Service/                 # 业务服务层
│   └── UserService.php
├── Repository/              # 数据访问层
│   ├── UserRepositoryInterface.php
│   └── MySQLUserRepository.php
├── Entity/                  # 领域实体
│   └── User.php
├── DTO/                     # 数据传输对象
│   └── UserCreateDTO.php
├── Exception/               # 异常
│   └── BusinessException.php
└── Enum/                    # 枚举
    └── UserRole.php
```

### 完整示例

```php
<?php
// Entity — 纯数据结构，不含业务逻辑（贫血模型）
namespace App\Entity;

class User
{
    public function __construct(
        public readonly int $id,
        public string $name,
        public string $email,
        public UserRole $role,
        public readonly \DateTime $createdAt,
    ) {}
}

// DTO — 请求数据的强类型容器
namespace App\DTO;

readonly class CreateUserDTO
{
    public function __construct(
        public string $name,
        public string $email,
        public string $password,
    ) {}
}

// Repository Interface — 数据访问抽象
namespace App\Repository;

use App\Entity\User;

interface UserRepositoryInterface
{
    public function findById(int $id): ?User;
    public function findByEmail(string $email): ?User;
    public function save(User $user): User;
    public function delete(int $id): bool;
}

// Repository Implementation
namespace App\Repository;

use App\Entity\User;
use App\Enum\UserRole;

class MySQLUserRepository implements UserRepositoryInterface
{
    public function __construct(private \PDO $pdo) {}

    public function findById(int $id): ?User
    {
        $stmt = $this->pdo->prepare('SELECT * FROM users WHERE id = ?');
        $stmt->execute([$id]);
        $row = $stmt->fetch(\PDO::FETCH_ASSOC);
        
        return $row ? $this->hydrate($row) : null;
    }

    public function save(User $user): User
    {
        if ($user->id === 0) {
            $stmt = $this->pdo->prepare(
                'INSERT INTO users (name, email, role, created_at) VALUES (?, ?, ?, NOW())'
            );
            $stmt->execute([$user->name, $user->email, $user->role->value]);
            return new User(
                (int)$this->pdo->lastInsertId(),
                $user->name, $user->email, $user->role, new \DateTime()
            );
        }
        
        $stmt = $this->pdo->prepare('UPDATE users SET name=?, email=?, role=? WHERE id=?');
        $stmt->execute([$user->name, $user->email, $user->role->value, $user->id]);
        return $user;
    }

    private function hydrate(array $row): User
    {
        return new User(
            (int)$row['id'],
            $row['name'],
            $row['email'],
            UserRole::from($row['role']),
            new \DateTime($row['created_at']),
        );
    }
}

// Service — 业务逻辑
namespace App\Service;

use App\DTO\CreateUserDTO;
use App\Entity\User;
use App\Enum\UserRole;
use App\Exception\BusinessException;
use App\Repository\UserRepositoryInterface;

class UserService
{
    public function __construct(
        private UserRepositoryInterface $repository,
    ) {}

    public function createUser(CreateUserDTO $dto): User
    {
        // 业务规则：邮箱不能重复
        if ($this->repository->findByEmail($dto->email) !== null) {
            throw new BusinessException('邮箱已被注册');
        }

        $user = new User(
            id: 0,
            name: $dto->name,
            email: $dto->email,
            role: UserRole::Member,
            createdAt: new \DateTime(),
        );

        return $this->repository->save($user);
    }
}

// Controller — 接收请求，返回响应
namespace App\Http\Controllers\Api;

use App\DTO\CreateUserDTO;
use App\Service\UserService;

class UserController
{
    public function __construct(
        private UserService $userService,
    ) {}

    public function create(): \JsonResponse
    {
        $dto = new CreateUserDTO(
            name: $_POST['name'] ?? '',
            email: $_POST['email'] ?? '',
            password: $_POST['password'] ?? '',
        );

        // 验证
        $errors = $this->validate($dto);
        if (!empty($errors)) {
            return new \JsonResponse(['errors' => $errors], 422);
        }

        $user = $this->userService->createUser($dto);
        return new \JsonResponse(['id' => $user->id], 201);
    }
}
```

## 充血模型 vs 贫血模型

### 贫血模型（传统）

```php
<?php
// Entity只是数据容器，业务逻辑在Service中
class Order {
    public string $status;
    public float $total;
}

class OrderService {
    public function cancel(Order $order): void {
        // 业务规则在Service中
        if ($order->status !== 'pending') {
            throw new \Exception('Only pending orders can be cancelled');
        }
        $order->status = 'cancelled';
    }
}
```

### 充血模型

```php
<?php
// Entity包含自己的业务逻辑和不变量保护
class Order
{
    private string $status = 'pending';
    private float $total;
    private array $items = [];

    public function addItem(Product $product, int $quantity): void
    {
        if ($this->status !== 'pending') {
            throw new \DomainException('只能修改待处理订单');
        }
        $this->items[] = new OrderItem($product, $quantity);
        $this->recalculateTotal();
    }

    public function cancel(): void
    {
        if ($this->status !== 'pending') {
            throw new \DomainException('只能取消待处理订单');
        }
        $this->status = 'cancelled';
    }

    public function pay(): void
    {
        if ($this->status !== 'pending') {
            throw new \DomainException('只能支付待处理订单');
        }
        if ($this->total <= 0) {
            throw new \DomainException('订单金额必须大于0');
        }
        $this->status = 'paid';
    }

    private function recalculateTotal(): void
    {
        $this->total = array_sum(array_map(
            fn(OrderItem $item) => $item->getSubtotal(),
            $this->items
        ));
    }
}
```

充血模型的Service变成薄层——只做事务编排：

```php
<?php
class OrderService {
    public function placeOrder(array $productIds, int $userId): Order {
        $order = new Order($userId);
        foreach ($productIds as $id) {
            $product = $this->productRepo->find($id);
            $order->addItem($product, 1);
        }
        $this->orderRepo->save($order);
        return $order;
    }
}
```

## 六边形架构（端口与适配器）

六边形架构将业务逻辑完全隔离，通过端口（接口）与外部世界通信：

```
                ┌──────────────────┐
                │   业务核心(域)    │
                │                  │
   HTTP适配器 ←──┤  端口(接口)     ├──→ MySQL适配器
                │                  │
   CLI适配器  ←──┤  端口(接口)     ├──→ Redis适配器
                │                  │
   消息队列   ←──┤  端口(接口)     ├──→ 外部API适配器
                └──────────────────┘
```

```php
<?php
// 端口（接口）定义在业务核心中
namespace App\Domain\Port;

interface OrderRepositoryPort {
    public function save(Order $order): void;
    public function findById(int $id): ?Order;
}

interface PaymentPort {
    public function charge(float $amount, string $currency): string;
}

interface NotificationPort {
    public function notifyOrderCreated(Order $order): void;
}

// 业务用例（Application Service）
namespace App\Domain\UseCase;

class PlaceOrderUseCase
{
    public function __construct(
        private OrderRepositoryPort $orderRepo,
        private PaymentPort $payment,
        private NotificationPort $notifier,
    ) {}

    public function execute(PlaceOrderCommand $cmd): Order
    {
        $order = Order::create($cmd->userId, $cmd->items);
        $this->orderRepo->save($order);
        
        $paymentId = $this->payment->charge($order->getTotal(), 'CNY');
        $order->markAsPaid($paymentId);
        $this->orderRepo->save($order);
        
        $this->notifier->notifyOrderCreated($order);
        
        return $order;
    }
}

// 适配器在外层实现接口
namespace App\Adapter\Persistence;

class MySQLOrderAdapter implements OrderRepositoryPort {
    public function __construct(private \PDO $pdo) {}
    public function save(Order $order): void { /* SQL */ }
}
```

## 架构选型建议

| 项目规模 | 推荐架构 | 理由 |
|----------|----------|------|
| 小型CRUD | 贫血模型+分层 | 简单直接，开发快 |
| 中型业务 | 充血模型+分层 | 业务逻辑内聚，易于维护 |
| 复杂业务 | 六边形/DDD | 业务核心隔离，可替换基础设施 |
| 微服务 | 六边形+模块化 | 每个服务独立，端口适配 |

## 面试常见追问

**Q: 分层架构最大的问题是什么？**
A: 容易退化成"胖Service"——所有业务逻辑堆积在Service层，Entity沦为数据容器。解决方法是引入充血模型，将业务逻辑内聚到Entity/Value Object中。

**Q: 充血模型和DDD是一回事吗？**
A: 不是。充血模型是DDD战术设计的一部分。DDD还包括聚合根、值对象、领域事件、限界上下文等概念。充血模型可以不用DDD，但DDD一定用充血模型。

**Q: 六边形架构和洋葱架构有什么区别？**
A: 核心思想相同：业务逻辑在中心，基础设施在外层。洋葱架构强调层级依赖方向（外层依赖内层），六边形强调端口/适配器的对称性。实际中两个术语常混用。

**Q: Repository模式和直接用Model有什么区别？**
A: Repository封装了数据访问细节，返回领域对象。Model（如Eloquent Model）同时承担数据访问和数据结构职责，违反SRP。Repository的好处是可替换底层存储、方便Mock测试。
